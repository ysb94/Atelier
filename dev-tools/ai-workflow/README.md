# Atelier 노션 개발 자동화

노션의 `E&J 공통 할 일`에서 지정한 업무를 PC의 Cursor로 작업하고 Codex로 검토한다.
운영 앱·라우트·배포 번들에는 연결하지 않는 개발 전용 도구다.

## 실행과 연결

`npm run dev`가 Vite, 구조도(4318), 자동화 관리자(4319)를 함께 실행한다.
`http://127.0.0.1:4319/health`에서 설정 대기·진행·오류를 확인한다.
연결이 없으면 자동화만 대기하고 개발 서버는 계속 실행한다.
개발 서버 없이 관리자를 실행하려면 `npm run ai:watch`, 연결 점검은 `npm run ai:doctor`다.
같은 프로젝트의 기존 관리자는 재사용하며 한 번에 한 업무만 실행한다.
PC가 꺼지거나 절전 중이면 실행되지 않는다. 관리자 재실행 후 미전송 기록을 먼저 재시도한다.

필요한 최초 설정:

1. Cursor CLI 로그인: `npm run ai:login`. 편집기 로그인과 CLI 로그인이 다를 수 있다.
2. Notion Developer portal에서 관리자용 내부 연결을 만들고 해당 업무 DB를 연결에 공유한다.
3. `.env.example`을 참고해 이 폴더의 `.env.local`에 `NOTION_TOKEN`을 넣는다.
   토큰은 노션 페이지·대화·`VITE_*`·Git에 넣지 않는다. 관리자가 파일 변경을 다음 확인 주기에 읽는다.
4. Cursor 프로젝트/사용자 MCP와 로컬 노션·Supabase 플러그인의 기존 공개 서버 정의를
   격리된 CLI 작업 폴더에서 사용하고, ACP 작업 세션이 해당 CLI 연결을 재사용한다.
   IDE 설정 파일을 바꾸거나 OAuth 비밀값을 복사하지 않는다.
   CLI에서 OAuth 재로그인이 필요할 수 있다. 설정 발견은 연결 성공의 증거가 아니다.
   대시보드 팀 MCP는 ACP 지원 대상이 아니다. 사용자/프로젝트 MCP 인증과 실제 도구 호출을 확인한다.
5. Codex CLI 인증을 확인한다. 검토는 별도 읽기 전용 실행이며 이 Codex 대화창을 직접 조작하지 않는다.

Cursor 계정 로그인과 MCP 서비스 로그인은 별개다. 편집기에 연결된 OAuth가 CLI에 자동으로
공유되는 것으로 가정하지 않는다. `NOTION_TOKEN`은 관리자가 업무를 조회·기록할 때 쓰며,
Cursor의 원격 노션 MCP OAuth 로그인은 별도다.
`npm run ai:mcp:status`로 실제 서비스 인증 상태를 확인한다. `requires_authentication`이면
`npm run ai:mcp:login -- notion`(또는 `supabase`)을 실행하고 브라우저에서 로그인한다.
서비스별로 하나씩 진행한다. IDE 설정은 변경하지 않으며, 공개 서버 주소만 `.runtime`의
격리된 점검 폴더에 기록한다. 비밀 헤더가 있는 서버는 이 로그인 도우미의 대상이 아니다.
Cloudflare는 사용자 요청으로 `excludedMcpServers`에 등록했다. 자동화의 플러그인 로딩,
ACP 연결 구성, 연결 점검·로그인 대상에서 모두 제외한다.

공식 Cursor Windows CLI를 `.runtime/cursor/package/dist-package`에 설치하면 자동 발견한다.
다른 실행 파일은 `.env.local`의 `ATELIER_CURSOR_BIN`, `ATELIER_CODEX_BIN`으로 지정한다.
CLI 프로그램은 원래 로그인 저장소를 이용하며 이 도구가 OAuth 비밀값을 복사하지 않는다.

## 노션에서 업무 실행

`AI 요청`: 할 작업을 구체적으로 적는다.
`AI 완료 기준`: 보존할 동작, 확인할 결과와 필요한 검증을 적는다.
`AI 허용 파일`: 정확한 상대 파일 경로를 줄바꿈 또는 쉼표로 적는다(최대 30개).
`AI 자동 실행`: 체크한다. `AI 상태`: `대기`로 지정한다.
`AI 실행 순서`: 낮은 숫자부터 실행한다. 기존 `진행`은 미착수 → 진행 중 → 완료로 이어진다.

지시·보고·검토 기록은 업무 본문에 회차별로 추가한다. 업무의 원래 본문은 덮어쓰지 않는다.
`AI 결과`에는 최근 요약, `AI 반복 횟수`에는 회차가 표시된다.
작업 중 요청·기준·허용 파일을 바꾸면 확인 필요로 중단한다.
중지하려면 `AI 상태=중지` 또는 자동 실행 체크를 해제한다. 확인 주기는 작업 중 10초다.
중단된 작업은 파일 변경과 오류를 확인하고 `AI 요청`을 갱신한 뒤 대기로 지정한다.
같은 지시 버전의 완료/중단 기록은 자동 재실행하지 않는다.

## 작업과 검토

- Cursor는 ACP로 실행하며 허용 파일을 지정한다. 클라이언트 파일 쓰기 요청도 범위를 검사한다.
  Cursor 내부 도구의 수정은 전체 스냅샷으로 다시 확인하며 범위 밖 변경·동시 수정은 확인 필요로 중단한다.
- Cursor에 터미널 실행을 맡기지 않는다. 파일 편집 뒤 변경 범위 확인과 검증은 관리자가 수행한다.
- 작업 시작 시점의 실제 파일을 기록해 기존 미커밋 변경과 이번 작업 diff를 구분한다.
- 구조도에서 해당 파일과 직접 연결만 전달한다. 매 조회마다 AI를 호출하지 않는다.
- 구조도 갱신과 설정된 검증 스크립트를 실행하고 실제 로그를 검토자에게 전달한다.
- Codex는 읽기 전용으로 요청·완료 기준·실제 diff·검증 결과를 검토한다.
- 기준별 증거, 검증 통과, 실제 변경이 모두 있어야 완료를 기록한다.
- 수정 지시 → Cursor 재작업 → 재검토는 최초 작업 포함 총 3회까지다.
- 노션 기록 실패는 로컬 outbox로 보관한다. 기록 재시도만으로 코드 작업을 반복하지 않는다.
- 비정상 종료·동시 수정·범위 밖 변경은 자동으로 되돌리지 않고 확인 필요로 남긴다.

MCP 설정을 찾았다고 모든 도구를 자동 승인하지 않는다. SQL 실행·마이그레이션·알 수 없는 요청은
사용자 확인으로 전환한다. 현재 연결의 사전 승인 설정도 최초 시험에서 확인해야 한다.
DB 스키마·삭제·대량 수정은 `docs/architecture/SUPABASE.md`의 승인·백업 규칙을 따른다.
자동화 지시로 커밋·푸시·배포를 수행하지 않는다.

`config.json`에서 검사 명령을 지정한다. 개발자만 검토 명령을 변경한다.
로컬 설정이 필요하면 `config.local.json`에 포트·확인 간격 등을 지정한다.
검증: `npm run verify:ai-workflow`. 이 테스트의 Cursor/Codex/Notion은 테스트 대역이며
실제 연결 시험과 구분한다. 실제 실행 증거는 노션 업무와 `.state/runs`에 남는다.

## 파일 역할

| 파일 | 역할 |
| --- | --- |
| settings.mjs / doctor.mjs | 설정·연결 점검·비밀값 숨김 |
| notion.mjs | 노션 업무 조회와 결과 기록 |
| acp.mjs | 기존 Cursor 도구 연결과 작업 실행 |
| mcp.mjs | 서비스별 MCP 로그인·인증 상태 확인 |
| reviewer.mjs | Codex 검토와 합격 형식 검증 |
| workspace.mjs | 구조도 범위 조회·작업 전후 코드 비교 |
| runner.mjs | 작업 → 검증 → 검토 → 수정/완료 순서 |
| store.mjs | 단일 실행 잠금·중복 방지·기록 재시도 |
| serve.mjs | 개발 서버와 함께 실행하는 로컬 관리자 |

개발 구조도는 앱 TS/JS 연결을 분석하므로 이 독립 도구의 내부 파일은 앱 지도에 추가하지 않는다.
이 표가 개발 도구의 연결 안내이며 앱 코드 작업 후에는 기존 구조도를 자동 갱신한다.

## 실제 연결 시험 기록

2026-10-12, `E&J 공통 할 일`의 합성 시험 업무
[자동화 연결 시험: 개발 도구 안내 문서 작성](https://app.notion.com/p/3f763ce0dccd813eb5acd35563a7da97)을 실행했다.
Cursor가 `SMOKE_RESULT.md`를 보완했고, 독립 Codex 검토에서 서버 종료 설명의 오류를 찾아
수정 지시를 노션에 기록했다. Cursor가 해당 문장을 수정한 뒤 2회차 검토에서 합격했다.
관리자가 `AI 상태=완료`, `진행=완료`를 기록했으며 노션에서 다시 조회해 확인했다.
두 회차 모두 구조도 갱신·lint·build·진단·구조도 검증을 통과했고, 이번 작업의 변경은 안내 문서 한 파일뿐이었다.
운영 업무·DB 데이터 조회와 변경은 시험에 포함하지 않았다.
별도 CLI 인증을 마친 후 노션·Supabase는 `ready` 상태와 도구 목록을 확인했다.
실제 Cursor ACP 세션에서도 합성 시험 페이지 하나를 노션 MCP로 읽어 제목·완료 상태를 확인했다.
Cloudflare는 사용자가 연결을 원하지 않아 인증을 중단하고 자동화 대상에서 제외했다.
이 문서 작업의 완료가 업무·DB 데이터 조회 시험의 완료를 의미하지는 않는다.
Cloudflare 제외와 CLI 연결 재사용을 적용한 최종 구성에서도 같은 안내 문서의 인증 설명을
Cursor가 보완하고 검증 5개·독립 Codex 검토를 통과했다. 노션의 두 완료 속성을 재조회해 확인했다.
자동화 제어 회귀 검증 15개도 통과했다.
