# Atelier 노션 개발 자동화

노션의 `E&J 메모·작업 카드`에서 `위치=자동화 할 일`로 선택한 메모를 Cursor로 작업하고 Codex로 검토한다.
운영 앱·라우트·배포 번들에는 연결하지 않는 개발 전용 도구다.

## 실행과 연결

`npm run dev`가 Vite, 구조도(4318), 자동화 관리자(4319)를 함께 실행한다.
`http://127.0.0.1:4319/health`에서 설정 대기·진행·오류를 확인한다.
연결이 없으면 자동화만 대기하고 개발 서버는 계속 실행한다.
개발 서버 없이 관리자를 실행하려면 `npm run ai:watch`, 연결 점검은 `npm run ai:doctor`다.
같은 프로젝트의 기존 관리자는 재사용하며 `maxParallelTasks: 2`로 최대 두 업무를 동시에 처리한다.
PC가 꺼지거나 절전 중이면 실행되지 않는다. 관리자 재실행 후 미전송 기록을 먼저 재시도한다.

필요한 최초 설정:

1. Cursor CLI 로그인: `npm run ai:login`. 편집기 로그인과 CLI 로그인이 다를 수 있다.
2. Notion Developer portal에서 관리자용 내부 연결을 만들고 해당 업무 DB를 연결에 공유한다.
3. `.env.example`을 참고해 이 폴더의 `.env.local`에 `NOTION_TOKEN`을 넣는다.
   토큰은 노션 페이지·대화·`VITE_*`·Git에 넣지 않는다. 관리자가 파일 변경을 다음 확인 주기에 읽는다.
4. Cursor 프로젝트/사용자 MCP와 로컬 노션·Supabase 플러그인의 기존 공개 서버 정의를
   격리된 CLI 작업 폴더에서 사용하고, ACP 작업 세션이 해당 CLI 연결을 재사용한다.
   IDE 설정 파일을 바꾸거나 OAuth 비밀값을 복사하지 않는다.
   CLI에서 OAuth 재로그인이 필요할 수 있다. 설정 발견은 연결 성공의 증거가 아니다.
   대시보드 팀 MCP는 ACP 지원 대상이 아니다. 사용자/프로젝트 MCP 인증과 실제 도구 호출을 확인한다.
5. Codex CLI는 ChatGPT 구독 계정으로 로그인한다. 검토는 별도 읽기 전용 실행이며 이 Codex 대화창을 직접 조작하지 않는다.

Codex 검토는 구독 로그인만 사용한다. 관리자는 시작 시 `codex login status`를 확인하고,
각 검토 호출 전에도 로그인 방식을 다시 확인한다. API 키·미로그인·확인되지 않은 방식이면
검토를 시작하지 않는다. 실제 호출에는 `forced_login_method="chatgpt"`와 `model_provider="openai"`를
지정하여 로그인 방식이나 공급자 설정이 중간에 바뀌어도 API 과금 경로로 전환하지 못하게 한다.
API 키를 요구하거나 구매·추가 크레딧 결제·다른 유료 공급자로의 자동 전환을 수행하지 않는다.
구독 사용량 부족이나 인증 오류로 호출이 실패하면 이유를 남기고 중단한다. 사용자는 포함 사용량의
한도가 갱신되거나 구독 로그인을 복구한 뒤 재개할 수 있다. Codex 구독 사용량은 CLI와 앱에서 합산된다.
이 설정은 Codex 인증·호출에 적용하며 Cursor 요금제 설정은 별도로 관리한다.

`reviewTransport: source-bundle`에서는 관리자가 작업 파일 전체와 직접 참조 소스를 읽고
검증 시점 해시를 대조하여 diff·검사 로그와 함께 Codex에 전달한다. 검토용 셸·앱 도구는
끄고 읽기 전용 샌드박스와 구독 로그인 제한을 유지한다. 클라우드 안에서 중첩 셸을
열지 않으므로 부모 실행기의 소켓 경로를 변경할 필요가 없다. 자료는 실행 기록의
`review-source.json`에 남긴다. 파일 불일치·크기 초과는 중단하며 증거를 자르지 않는다.
검토자가 추가 증거를 요구하면 확인 필요이며 합성 화면 검사를 실제 로그인으로 보고하지 않는다.

검토기의 파일 읽기·명령 실행 환경 오류는 구현 결함과 구분한다. 해당 오류가 기록된 검토는
Cursor 재작업으로 반복하지 않고 실행기 준비가 필요한 상태로 기록한다. 로그인 화면 검사
수단이 없거나 지시 준비에 실패한 경우에도 기존 답변을 다시 요구하지 않는다. 실행기에서
해결할 문제에는 '내 답변을 적고 위치를 다시 옮기라'는 공통 안내를 붙이지 않는다.

Cursor 계정 로그인과 MCP 서비스 로그인은 별개다. 편집기에 연결된 OAuth가 CLI에 자동으로
공유되는 것으로 가정하지 않는다. `NOTION_TOKEN`은 관리자가 업무를 조회·기록할 때 쓰며,
Cursor의 원격 노션 MCP OAuth 로그인은 별도다.
`npm run ai:mcp:status`로 실제 서비스 인증 상태를 확인한다. `requires_authentication`이면
`npm run ai:mcp:login -- notion`(또는 `supabase`)을 실행하고 브라우저에서 로그인한다.
서비스별로 하나씩 진행한다. IDE 설정은 변경하지 않으며, 공개 서버 주소만 `.runtime`의
격리된 점검 폴더에 기록한다. 비밀 헤더가 있는 서버는 이 로그인 도우미의 대상이 아니다.
Cloudflare는 사용자 요청으로 `excludedMcpServers`에 등록했다. 자동화의 플러그인 로딩,
ACP 연결 구성, 연결 점검·로그인 대상에서 모두 제외한다.

공식 Cursor Windows CLI를 `.runtime/cursor/package/dist-package`에 설치하면 자동 발견한다.
다른 실행 파일은 `.env.local`의 `ATELIER_CURSOR_BIN`, `ATELIER_CODEX_BIN`으로 지정한다.
CLI 프로그램은 원래 로그인 저장소를 이용하며 이 도구가 OAuth 비밀값을 복사하지 않는다.

## 화면별 메모에서 업무 실행

사이트 메뉴의 부서 → 화면에서 카드 제목과 필요한 본문을 적고, `위치`를 `자동화 할 일`로 옮긴다.
관리자는 `자동화 할 일 → 자동화 작업 중 → 완료`로 위치를 갱신하며 독립 업무는 최대 두 개까지 동시에 처리한다.
카드는 조사·지시 갱신과 다른 작업의 완료를 기다리는 동안 `자동화 할 일`에 남는다.
최신 지시 저장과 확인을 마치고 작업용 Cursor를 호출할 때만 `자동화 작업 중`으로 옮긴다.
`자동화 단계`에는 구조 확인 → 작업 중 → 검토 중/수정 중 → 완료가 표시된다.
메모·직접 할 일은 자동 실행하지 않는다. 검증 또는 독립 검토를 통과하지 못한 카드는 완료하지 않는다.

작업을 넘기기 직전에 카드를 다시 읽는다. 별도의 읽기 전용 조사 세션이 최신 화면·영역·본문·내 답변,
이전 작업 결과·확인 질문과 실제 구조도/코드를 조사한다. 이 세션은 기존 Cursor ACP의 읽기·검색
허용만 사용하며 파일 편집과 터미널 명령을 허용하지 않는다. 지시를 저장한 뒤 작업용 Cursor를 호출한다.
연결된 화면·공통 코드·API의 근거로 요청, 완료 기준, 정확한 허용 파일(최대 30개), 필요한 기능 검증을 준비한다.
`AI 요청`·`AI 완료 기준`·`AI 허용 파일`은 관리자가 준비해 카드의 상세 속성에 기록한다.
이전 AI 요청·완료 기준·허용 파일은 자동 생성된 참고 자료이며 그대로 물려받지 않는다.
현재 원문과 답변을 기준으로 요청·완료 기준·파일 범위와 구현/검증 작업 종류를 매번 다시 작성한다.
사용자가 문제가 남았다고 답했다면 원인 조사·수정 작업으로 준비하고 예전 검증 전용 지시를 제거한다.
답변이 어떻게 반영됐는지 조사 기록에 남기며 이미 답한 질문을 반복하지 않는다. 조사 결과가 답변을
누락하거나 보고된 문제를 검증 전용으로 분류하면 편집 전에 거부하고 한 번 다시 준비한다.
허용 파일은 최신 원문에서 요구한 범위와 실제 연결 근거로 선택하며 경로·개수·DB 작업 제한을 검사한다.
사이트의 일반적 구현 선택은 기존 규칙을 따르되,
회사 정책·역할 면제 범위·필수 원본 데이터 등 알 수 없는 사실은 지어내지 않는다.
실제 입력이나 선행 작업이 필요하면 `위치=확인 필요`, `확인 질문`·`작업 결과`에 이유를 기록한다.
`작업 결과`에는 쉬운 멈춤 이유와 처리 방법을, `확인 질문`에는 답할 항목과 직접 처리 후 알려줄 내용을 기록한다.
`내 답변` 또는 메모를 보완하고 다시 `자동화 할 일`로 옮기면 최신 입력으로 처리한다.
사용자가 AI 요청·완료 기준·허용 파일을 직접 점검하거나 갱신할 필요는 없다.
답변 입력만으로 작업을 시작하지 않으며 새 할 일을 자동으로 쪼개 생성하지 않는다.

`실행 순서`가 지정된 낮은 숫자부터, 같은 순서이면 먼저 등록한 메모부터 처리한다.
지시·Cursor 대화·검토 기록은 개발 전용 로컬 실행 기록에만 보관하고 원래 본문은 보존한다.
노션 본문에는 검토가 통과한 뒤 비전공자용 완료 보고서만 남긴다.
보고서는 메모 출처, 실제 작업 화면, 바뀐 점, 사용 방법, 실제 확인 결과, 적용 상태와 완료 시각을 담는다.
코드 파일명·함수명·원시 검사 로그를 나열하지 않으며 운영 사이트 게시 여부를 실제 증거대로 구분한다.
완료 보고서는 같은 기록을 재전송해도 중복 생성되지 않고 원문 메모의 새 버전으로 간주되지 않는다.
`작업 결과`에는 최근 요약, `실행 회차`에는 회차가 표시된다. 보고·계획·상태 갱신은 메모 버전을 바꾸지 않는다.
작업 중 제목·본문·출처·내 답변 또는 준비된 요청/기준/파일을 바꾸면 확인 필요로 중단한다.
`위치`를 메모·직접 할 일 등 자동화 밖으로 옮기거나 `자동화 단계=중지`로 바꾸면 중지한다.
확인 주기는 작업 중 10초다. 본문을 읽은 뒤 최신 위치·중지·원문/계획 버전을 확인하고,
완료 보고서를 추가하기 직전에도 다시 확인하여 관찰한 취소·변경을 보존한다.
Notion API의 조회와 쓰기는 원자적인 조건부 갱신이 아니다. 마지막 조회 직후부터 쓰기 요청 사이의
동시 변경까지 완전히 보장할 수는 없다. 중지할 때는 위치를 옮기고 실행기의 중단 상태를 확인한다.
완료/중단 상태에 둔 카드는 자동 재실행하지 않는다. 사용자가 끝난 카드를 다시 `자동화 할 일`로
옮기면 같은 메모 버전이어도 새 조사 기록을 만들고 최신 코드로 지시를 갱신한다. 이전 실행 기록은 보존한다.
재등록은 위치로 판단하므로 자동화 단계가 대기로 바뀌었어도 이전 중단 기록 때문에 건너뛰지 않는다.
본문의 자동 생성된 'Atelier AI 확인 필요 안내'는 최근 작업 결과·확인 질문과 함께 갱신한다.
재개·완료할 때 예전 안내를 제거하며 원문 메모와 내 답변은 보존한다. 안내 저장 실패는 기존
기록 전송 재시도로 복구하고, 이미 재등록된 카드에 지난 중단 안내를 다시 붙이지 않는다.
조사 중 입력이 바뀌거나 준비 중 다른 작업과 겹쳐 기다린 경우 캐시한 계획을 편집기로 보내지 않는다.
다음 시작 때 최신 카드와 코드로 다시 조사하고, 진행 중 사용자 변경·취소 확인도 계속 수행한다.

## 작업과 검토

`verify:browser-images`, `verify:browser-deadline`, `verify:browser-attendance`는
Playwright와 Chromium으로 실제 화면 컴포넌트의 등록·수정·표시를 검사한다.
Chromium 경로는 `ATELIER_CHROMIUM_BIN` 또는 `/usr/bin/chromium`이다.
검사 전용 Vite 서버만 테스트 프로필·오프라인 응답을 사용하며 앱의 인증 코드와
운영 라우트에는 연결하지 않는다. 외부 네트워크와 DB 쓰기는 차단한다.
실제 계정 로그인·RLS·DB 지속성은 이 검사로 확인할 수 없다. 결과와 화면 캡처는
개발 전용 `.state/browser`에 남기고 검사 로그에 합성 검증 범위를 명시한다.
UI 시안 변경의 화면 증거로 사용할 수 있지만 실제 저장·권한 변경 작업의 대체 증거는 아니다.

- 각 업무는 현재 미커밋 변경까지 복제한 별도 임시 작업 공간에서 조사·편집·검사한다.
  인증·환경·실행 기록·DB 백업은 복사하지 않고, 설치된 패키지만 재사용하며 빌드 캐시는 분리한다.
- 수정 파일과 구조도에서 따라간 읽기 의존이 겹치는 업무는 대기한다. 앞 업무가 끝나면 최신 코드로 다시 조사한다.
- 조사와 편집은 병렬로 진행하고, 개발 화면에 결과를 합치는 단계는 하나씩 진행한다.
  사용자 변경 여부를 재확인한 뒤 합친 코드의 실제 검사와 독립 Codex 검토가 통과해야 완료한다.
- 통합 검토에서 수정이 필요하면 관리자가 방금 적용한 후보만 복원하고 격리 작업 공간에서 보완한다.
  사용자가 그 파일을 바꿨다면 해당 변경을 보존하고 확인 필요로 중단한다. 운영 배포나 Git 커밋은 하지 않는다.
- 다시 켰을 때 중단된 실행은 확인 필요로 표시한다. 같은 편집을 자동 반복하지 않는다.
  미전송 완료 보고서만 재전송하며, 실제 완료 시각은 유지한다.
- `/health`에 `limit`, `activeCount`, 업무별 `tasks`와 충돌 대기 목록이 표시된다.
  선택 작업의 연결이 겹치거나 입력이 필요하면 실제 동시 작업 수는 두 개보다 적을 수 있다.

- Cursor는 ACP로 실행하며 허용 파일을 지정한다. 클라이언트 파일 쓰기 요청도 범위를 검사한다.
  Cursor 내부 도구의 수정은 전체 스냅샷으로 다시 확인하며 범위 밖 변경·동시 수정은 확인 필요로 중단한다.
- Cursor에 터미널 실행을 맡기지 않는다. 파일 편집 뒤 변경 범위 확인과 검증은 관리자가 수행한다.
- 작업 시작 시점의 실제 파일을 기록해 기존 미커밋 변경과 이번 작업 diff를 구분한다.
- 구조도에서 해당 파일과 직접 연결만 전달한다. 매 조회마다 AI를 호출하지 않는다.
- 구조도 갱신과 설정된 검증 스크립트를 실행하고 실제 로그를 검토자에게 전달한다.
- Codex는 읽기 전용으로 요청·완료 기준·실제 diff·검증 결과를 검토한다.
- 기준별 증거, 검증 통과, 실제 변경이 모두 있어야 완료를 기록한다.
- 검증 전용으로 지정한 실행은 파일 편집을 허용하지 않는다. 이 경우 파일 변경 대신 실제 검증 로그와 독립 검토의 기준별 증거가 있어야 완료한다.
- 완료 시 `완료일`에 한국 날짜, `자동화 완료 시각`에 실제 완료 날짜·시간을 저장하고 본문에도 한국시간으로 기록한다.
  노션 날짜 속성은 초를 생략해 분 단위로 저장한다. 보고서 본문과 로컬 실행 기록에는 실제 완료 시각의 초까지 남긴다.
  저장된 날짜는 나중에 본문을 수정해도 바뀌지 않는다. 이 기록은 실행기가 완료한 작업에 적용되며,
  사용자가 직접 위치만 완료로 바꾼 카드의 자동 날짜 기록은 별도의 노션 자동화 규칙이 필요하다.
- 수정 지시 → Cursor 재작업 → 재검토는 최초 작업 포함 총 3회까지다.
- 노션 기록 실패는 로컬 outbox로 보관한다. 기록 재시도만으로 코드 작업을 반복하지 않는다.
- 비정상 종료·동시 수정·범위 밖 변경은 자동으로 되돌리지 않고 확인 필요로 남긴다.

MCP 설정을 찾았다고 모든 도구를 자동 승인하지 않는다. SQL 실행·마이그레이션·알 수 없는 요청은
사용자 확인으로 전환한다. 현재 연결의 사전 승인 설정도 최초 시험에서 확인해야 한다.
DB 스키마·삭제·대량 수정은 `docs/architecture/SUPABASE.md`의 승인·백업 규칙을 따른다.
자동화 지시로 커밋·푸시·배포를 수행하지 않는다.

`config.json`에서 검사 명령을 지정한다. 개발자만 검토 명령을 변경한다.
로컬 설정이 필요하면 `config.local.json`에 포트·확인 간격 등을 지정한다.
검증: `npm run verify:ai-workflow`. 이 테스트의 Cursor/Codex/Notion은 테스트 대역이며
실제 연결 시험과 구분한다. 실제 실행 증거는 노션 업무와 `.state/runs`에 남는다.

## 파일 역할

| 파일 | 역할 |
| --- | --- |
| settings.mjs / doctor.mjs | 설정·연결 점검·비밀값 숨김 |
| notion.mjs | 노션 업무 조회와 결과 기록 |
| planner.mjs | 읽기 전용 조사 세션의 최신 메모·답변 조사와 실행 지시 재작성 |
| acp.mjs | 기존 Cursor 도구 연결과 작업 실행 |
| mcp.mjs | 서비스별 MCP 로그인·인증 상태 확인 |
| reviewer.mjs | Codex 검토와 합격 형식 검증 |
| codex-subscription.mjs | 구독 로그인 확인과 API 키·다른 공급자로의 과금 전환 차단 |
| report.mjs | 비전공자용 완료 보고서 검증·노션 표시 |
| workspace.mjs | 구조도 범위 조회·작업 전후 코드 비교 |
| runner.mjs | 작업 → 검증 → 검토 → 수정/완료 순서 |
| parallel.mjs / isolation.mjs | 최대 두 작업의 공간 분리·충돌 대기·결과 통합 |
| store.mjs | 단일 실행 잠금·중복 방지·기록 재시도 |
| serve.mjs | 개발 서버와 함께 실행하는 로컬 관리자 |

개발 구조도는 앱 TS/JS 연결을 분석하므로 이 독립 도구의 내부 파일은 앱 지도에 추가하지 않는다.
이 표가 개발 도구의 연결 안내이며 앱 코드 작업 후에는 기존 구조도를 자동 갱신한다.

2026-10-12, `E&J 공통 할 일`의 합성 시험 업무
[자동화 연결 시험: 개발 도구 안내 문서 작성](https://app.notion.com/p/3f763ce0dccd813eb5acd35563a7da97)을 실행했다.
