## 충돌 해결

- Cursor의 업체 단위 목록, 88코드 찾기 패널·중복 탭 제거, 공지·송장 안내·마이페이지 이동을 유지했다.
- 헤더는 공통 연결과 업체 전용 값으로 분리하고 기존 UUID·소스·권한을 유지했다.
- 같은 업체에 기존 저장 연결이 여러 개면 헤더 설정에서 연결을 명시한다. 다른 연결의 전용 값을 복사·덮어쓰기하지 않는다. 선택한 연결에 등록되지 않은 코드는 전용 값 수정을 막는다.
- 엑셀 양식에 표시 중인 모든 헤더를 넣되 반영 대상은 코드 연결·상태뿐이다. 이름을 바꿔도 소스 키로 인식하고 전용 항목과 혼동되는 별칭을 차단한다. 실제 XLSX 다운로드도 검사했다.
- 일괄 업로드 화면도 선택한 업체 연결의 헤더를 읽는다. 기존 브랜드 헤더는 조회만 하며 자동 생성·저장하지 않는다.
- Cursor 변경에 남은 미사용 `groupJobsByPartner` 함수만 제거해 TypeScript 빌드를 통과시켰다. 실행되는 출고 로직은 변경하지 않았다.

## 검증

Node 22에서 통과:

- `npm run build`, `npm run lint` (기존 경고 유지)
- `verify:usage-headers`, `verify:code-usage`, `verify:usage-headers-db` (PostgreSQL/RLS 42개)
- `verify:usage-headers-browser`: 실제 React 화면, 공통 값 보호, 담당자, 업체·저장 연결 격리, 숨김 복구, 실패 시 초안 보존, XLSX 다운로드
- `verify:company-notices`, `verify:invoice-work-briefing`, `verify:invoice-step-compute`, `verify:outbound-partner`, `verify:diagnostics`, `verify:workspace-tabs`, `verify:company-paths`
- `npx tsx --tsconfig tsconfig.app.json src/lib/outbound/partner-outbound-chart.verify.ts`: 기존 차트 회귀 및 단일/복수 지점·채널 표시
- `verify:structure-map` 9개, `structure:map` 최신 생성

`verify:ai-workflow`는 **158개 중 151개 통과, 7개 실패**했다. 6개는 Windows 테스트용 파일 심볼릭 링크 권한(EPERM) 관련이고 1개는 임시 폴더 정리 잠금(EBUSY)이다. 전체 통과로 기록하지 않는다. 시스템 권한이나 검사를 우회하도록 코드를 바꾸지 않았고, 업무 자동 실행도 다시 켜지 않았다.

## DB·로컬 파일

이번 통합에서는 DB를 변경하지 않았다. 기존 헤더 DB 적용은 [검증 기록](../architecture/USAGE_PARTNER_HEADERS_VERIFICATION.md)을 참고한다.

Cursor 원본 마이그레이션 2개는 파일명 시각과 실제 MCP 이력 시각이 다르다. 읽기 전용 DB 조회로 공백을 제외한 SQL 지문이 같음을 확인했다.

| 원본 파일 | 실제 적용 버전 |
| --- | --- |
| `20261020021000_company_notices.sql` | `20261020021607` |
| `20261020061000_usage_code_columns.sql` | `20261020064032` |

이 파일명 정리는 자동 승인 검토에서 DB 이력 불일치 위험으로 거절되어 실행하지 않았다. 원본 파일과 DB 이력을 보존했다. 향후 `supabase db push` 전에 이 두 파일과 적용 이력의 동기화 방법을 별도로 확인해야 한다. 개발 화면 실행에는 조정이 필요하지 않다.

원본 폴더의 `docs/backups/` 미추적 파일 8개, 인증값·`.env.local`·실행 기록은 커밋하지 않았다. 집에서는 기존 로컬 연결 설정을 사용한다.
