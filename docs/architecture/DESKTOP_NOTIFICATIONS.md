# PC 업무 알림

사이트가 열린 상태에서 최소화하거나 다른 탭을 보는 사용자를 위한 시스템 알림이다.
탭 종료 이후의 서버 웹 푸시는 이번 범위에 포함하지 않는다. 브라우저 절전·탭 중지,
OS 알림 차단·집중 모드에서는 지연되거나 배너가 표시되지 않을 수 있다.

## 동작과 권한

- 실제 로그인 사용자와 프로필이 같은 활성 직원에게만 제공한다.
- 최초 안내의 ‘알림 켜기’ 클릭에서 브라우저 권한을 요청한다. ‘나중에’는 현재
  헤더가 유지되는 동안 안내를 닫는다. 종 모양 알림창에서 다시 켤 수 있다.
- 허용·차단은 브라우저 권한을 따르며, 사이트의 끄기는 사용자·브라우저별 UI 설정이다.
- 종합 알림과 같은 서버 조회 결과 및 공개 메뉴 접근 필터를 사용한다.
  현재 연결된 회의, 연차, 지각 사유서, 신청·승인 결과, 외근, 퇴근 확인이 대상이다.
- 첫 성공 조회는 기준으로만 삼고 과거 미확인 알림을 재생하지 않는다.
- 새 이벤트가 도착했고 현재 이벤트이며 미확인일 때, 숨겨진 문서에서만 표시한다.
  새 이벤트 여부는 알림 ID, 이벤트 버전, 회의 일정 버전으로 구분한다.
- 여러 탭은 전용 IndexedDB의 readwrite 트랜잭션으로 발송 판정을 직렬화한다.
  브라우저 UI 전달 캐시는 이벤트 식별자와 전달 시각만 최대 500건·7일 보관한다.
  업무 데이터 원본용 IndexedDB와 무관하며 본문·제목·업무 읽음 기록은 저장하지 않는다.
  이는 서버 읽음·처리 완료 상태가 아니며 업무 상태 조회에 사용하지 않는다.
- 제목과 정해진 처리 안내만 표시한다. 자유 입력 사유·처리 의견은 본문에 넣지 않는다.
- 클릭하면 현재 계정과 현재 이벤트를 확인하고 기존 상세 경로로 이동한다.
  클릭 자체는 읽음 저장을 호출하지 않는다. 상세 화면의 기존 권한·읽음 처리를 따른다.
- 읽음과 처리 완료는 기존 서버 원본을 사용한다. 승인·응답·본인 확인 대기는 유지한다.
- 계정 전환·로그아웃·컴포넌트 해제 시 생성했던 OS 알림을 닫는다.
- 기존 실시간 구독을 재사용하며 PC 알림이 켜진 경우에만 관련 30초 조회를
  백그라운드에서도 실행한다. 전역 창 포커스 재조회 정책은 변경하지 않는다.
- DB 스키마·권한·운영 데이터는 변경하지 않는다.

## 검증

- Node 버전: `.nvmrc`의 22.
- `npm run verify:desktop-notifications`: 모의 Notification API와 두 브라우저 탭으로
  허용 요청, 최초 안내, 과거 알림 생략, 중복 방지, 클릭, 읽음, 끄기, 보이는 탭,
  이벤트 재변경, 계정 전환 정리, 테스트 알림, 권한 차단을 확인한다.
- 이 검증은 실제 OS 배너 전달 성공을 증명하지 않는다. Windows Chrome 및
  macOS Safari/Chrome에서 실제 허용·최소화·클릭 이동·OS 설정을 확인해야 한다.
- 기존 My home 알림 상태·DB·브라우저 검증과 진단 검증, 빌드를 함께 확인한다.

주요 구현은 `src/lib/inbox/desktop-notifications.ts`,
`src/lib/inbox/use-desktop-notifications.ts`,
`src/components/layout/DesktopNotificationSettings.tsx`다.
