# 재고·예약·가용 원칙

이 문서는 Atelier의 재고 숫자 정의와 화면 원칙이다.
송장 예약·실재고 차감 UI는 아직 구현하지 않으며, 이후 스키마(`stock_*`,
`stock_reservations` 등)를 만들 때 이 정의를 따른다.

창고 화면의 연습 데이터는 아래 **연습 창고** 절을 따른다. 엑셀 원본을 유지한
채 사이트에만 교체 가능한 사본을 두고, 송장 예약이나 실재고 차감과 연결하지
않는다.

사은품 선착순 배정 원장(`invoice_gift_allocations`)은 행사 한도·주문 권리의
원본이다. 향후 재고 예약은 이 allocation을 참조할 수 있으나, 지금 단계에서는
재고 테이블과 직접 연동하지 않는다.

## 숫자 정의

| 용어 | 의미 | 음수 허용 |
| --- | --- | --- |
| 실재고 | 창고에 실제로 있는 수량 | 아니오. 출고는 실재고를 0 아래로 내리지 않는다 |
| 예약수량 | 출고 전 주문이 잡아 둔 수량 | 아니오 |
| 가용재고 | `실재고 - 예약수량` | 계산 결과는 0 미만이 될 수 있으나, 신규 예약은 가용재고가 있을 때만 허용하는 것을 기본으로 한다 |
| 부족수량 | 주문을 모두 맞추기 위해 더 필요한 수량 | 표시용. 실재고를 음수로 만들지 않는다 |
| 확정 입고 | 날짜가 확정된 입고 예정 수량 | 아니오 |
| 예상가용(날짜 D) | `실재고 + D일까지 확정입고 - (예약·약정)` | 계산값. 날짜별로 본다 |

약정은 아직 별도 원장을 두지 않는다. 도입 시에도 “이미 팔기로 확정한 수량”만
예약과 같은 차감축에 넣고, 실재고와 이중 차감하지 않는다.

## 화면 원칙

- 창고 화면의 대표 지표는 **실재고**다.
- MD·영업 화면의 대표 지표는 **가용재고**와 **날짜별 예상가용**이다.
- 같은 숫자를 화면마다 다른 이름으로 부르지 않는다. 위 표의 용어를 그대로 쓴다.

## 주문·사은품과 예약

1. 출고 전에는 주문·사은품 권리를 **예약**만 잡는다. 실재고는 건드리지 않는다.
2. 주문 취소·사은품 배정 취소 시에는 **예약만 해제**한다. 이미 출고된 건은
   출고 취소/반입 흐름으로 처리한다.
3. 출고 확정 시에는 `실재고`와 `예약`을 **함께** 줄인다.
   - 올바른 예: 실재고 10, 예약 3 → 출고 1 → 실재고 9, 예약 2, 가용 7
   - 잘못된 예: 가용만 먼저 줄이거나, 출고 때 실재고만 줄여 예약을 남겨 이중 차감
4. 사은품 선착순의 카운트 단위는 **실제 사은품 1개**다.
   - M번호별 방식은 `invoice_gift_quotas`의 `style_id`별 한도를 쓴다.
   - 전체 합계 방식은 요청 건의 `first_come_total_limit`을 모든 M번호가 공유한다.
     여러 종류를 섞어도 실제 사은품 합계가 100개이면 100개에서 종료한다.
   - 확정 배정(`invoice_gift_allocations`)이 두 방식 모두의 사용량 원장이다.
5. 작업 지시 포장재(Gift box L 등)는 지시가 적용된 주문만 센다.
   - 연결은 `invoice_work_instruction_products.style_id`다.
   - 산정은 지시의 `count_basis`(기본: 합포장당 1개)다.
   - 송장 별도 행이 아니며, 지금 단계는 오늘 작업 집계만 한다.
   - 향후 `stock_reservations`는 이 집계 수량을 예약으로 받는다. 사은품
     allocation과 포장재 집계를 같은 실재고에서 이중 차감하지 않는다.

## 예약발송(예발)과 사은품 권리

- 주문이 예약발송으로 이동해도, 이미 확정된 사은품 배정 권리는 유지한다.
- 행사 종료·한도 소진 이후에도, 예발에 묶인 기존 allocation은 자동 회수하지
  않는다. 취소 RPC로만 해제한다.
- 향후 `stock_reservations`를 만들 때는 `invoice_gift_allocations.id`를
  참조 가능하게 두고, 예약발송 주문의 사은품 예약을 같은 권리로 연결한다.
- 예발 화면·입고 후 자동 출고는 이 문서의 가용/예상가용 정의를 따른 뒤
  별도 구현한다.

## 연습 창고

엑셀(`상품업로드`)은 당분간 원본이다. 사이트에는 `sandbox` 연습 세트를 두고
`연습 데이터`로 표시한다. 최신 XLSX를 다시 올리면 기존 세트와 작업 이력은
삭제하지 않고 보관한 뒤 새 세트를 활성화한다. 보관한 세트는 복원할 수 있다.

- 자리는 상품 고정석이 아니다. 같은 박스가 다른 코드로 옮겨도 입고일은 유지한다.
- 사용 순서: `000000` 강제 우선의 일반 위치 → 일반 위치의 입고일 오름차순 →
  `//` 마지막 위치. 동률이면 원본 행번호다. `//`는 위치 문자열에서 분리해
  `is_final_location`으로 저장한다.
- 현재 적재는 미식별 박스 묶음(`warehouse_stock_positions`)이다. 향후 박스 ID
  (`warehouse_boxes`)는 한 박스가 M번호 1종·입고일 1개만 가진다. 첫 적재에서는
  박스 ID 테이블이 비어 있다.
- 박스창고에서는 박스 전체 단위로만 자리를 옮긴다. 일부 박스만 옮기면 원래
  입고일을 유지한 새 위치 행으로 나눈다. 출고창고 부족 시 박스를 충원한 뒤
  개봉해 낱개를 만든다.
- 잔여 박스와 개봉 낱개는 0 미만이 될 수 없다. 입고·이동·소진·실사·충원·개봉·
  세트 활성화는 RPC 트랜잭션으로 처리한다.
- 완전 중복 행은 원본 행번호별로 보존하고 `duplicate_suspect`로 표시한다.
  등록되지 않은 M번호·비정상 날짜·빈 자리도 제외하지 않고 검수한다.
