# 직원 1차 공개 범위

- 공개 판단은 `src/lib/company/release-access.ts` 한곳에서 수행한다. 실제 DB 권한을 부여하지 않는다.
- 일반 직원: My home의 내 근태·회의. 기존 지정 승인자/대체 승인자는 승인할 신청을 추가한다.
- 운영지원팀: 위 기본 화면과 운영지원 전체, 멤버·권한, 권한·담당자 설정.
- 물류팀: 위 기본 화면과 현재 물류 메뉴 전체(임시 화면 포함).
- 개발자·윤설빈·김준영은 확인한 계정 UUID로 공개 제한에서 제외한다. 직책·이름·is_admin은
  예외를 만들지 않는다. IP 기록 조회 등 기존 전용 권한은 넓히지 않는다.
- 부서는 확인한 회사·부서 UUID로 판정한다. 부서 소속이 수정·삭제·승인 권한을 만들지 않는다.
- 메뉴·탭·주소·알림 링크·KeepAlive 작업 탭에 같은 규칙을 적용한다. 비공개 자식은 실행하지 않고
  활성 화면에서만 My home으로 이동한다. 부서/승인자 변경 때 열린 화면도 다시 판정한다.
- 채팅은 기존대로 유지한다. 미공개 AI 도우미는 제한 대상 직원에게 실행하지 않는다.
- 물류 상품 상세의 예전 `/products/...` 링크는 물류 상세 경로로 연결한다. 전체 상품·데이터
  업로드·브랜드 관리 화면은 추가 공개하지 않는다. 기존 브랜드 선택과 상세 닫기 흐름은 유지한다.
- 출근·퇴근·신청·승인·로그인은 기존 동작 그대로다. 출근 장소·IP 차단은 없다.
  IP 기록 서버는 test·운영·로컬에서 인증된 기록을 받는다. 저장 실패는 출근을 막지 않는다.
- 검증: `verify:release-access`, `verify:release-access-browser`, 기존 근태·신청·로그인·회의·IP
  검증과 빌드. 가짜 데이터와 외부 요청 차단을 사용하며 운영 사용자/업무 데이터를 시험 변경하지 않는다.
- 구조도 갱신 뒤 이번 변경만 test에 커밋·push한다. main 반영은 화면 검수와 별도 승인 후 선별한다.
