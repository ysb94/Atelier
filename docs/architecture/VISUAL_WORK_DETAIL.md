# Visual 업무 상세 분류 탭

오른쪽 상세의 상단 띠는 요청 부서와 요청자를 표시한다. 제목 아래 정보표에는 총괄 관리자, 선택한 분류의 중간 관리자와 작업자, 업무 전체 상태·등록일·마감일·브랜드를 표시한다. 마감일은 확정 날짜를 우선하고, 날짜만 저장한 건은 일자를 표시한다. 메인 내용과 공통 참고 파일을 모든 분류에서 표시한다. 왼쪽 탭은 저장된 분류만 사용하며 좁은 화면에서는 가로로 표시한다. 선택한 분류의 저장 양식·본문·첨부와 댓글·답글이 함께 바뀐다. 본문과 참고 파일은 저장한 배치와 표시 크기를 사용하고 원본을 다운로드한다. 공유 링크에는 업무 ID와 선택 분류를 넣는다.

업무 메뉴의 `업무 관리`에서 분류 배정 정보·변경과 요청 전체의 접수·마감·완료 검수를 확인한다. 기존 분류 없는 대화는 댓글 영역의 `이전 댓글 보기`에서 원래 대화방 권한으로 열람한다. 분류가 없는 업무는 기존 상세를 사용한다.

분류 요청서의 본문에는 설정에 저장된 질문과 입력 안내를 읽기 전용 글줄로 표시한다. 질문마다 아래에서 답변을 쓰고 이미지와 파일을 배치한다. 필수 여부와 숫자·날짜 입력 기준은 질문 설정을 따른다. 답변 문자열은 기존 분류별 입력 값에 저장하고, 질문별 파일과 배치 정보는 기존 본문 첨부에 저장한다. 저장한 요청을 다시 열면 각 질문 아래에서 답변과 첨부를 확인할 수 있다.

댓글과 답글은 업무 ID와 저장된 분류 ID로 묶는다. 같은 회사의 활성 요청자, 업무 관리 담당자, 현재 해당 분류 담당자가 열람하며 취소·반려 시 읽기 전용이다. 담당자 변경 후에는 새 담당자가 같은 대화를 이어간다. 이전 담당자가 다른 분류에 배정됐더라도 이전 분류의 댓글과 파일 권한은 이어받지 않는다.

첨부는 댓글당 5개, 각 20MB까지 회사 비공개 Storage에 예약한다. 파일과 크기를 확인한 뒤 댓글을 공개하고, 같은 전송 번호로 재시도해도 중복되지 않는다. 실패한 임시 파일은 정리할 수 있으며 게시한 파일은 전송 실패 정리 경로에서 삭제할 수 없다. 요청 삭제 시 기존 삭제·재조회 절차로 분류 첨부도 정리한다. 댓글 조회는 열린 업무 탭과 선택 분류에서만 실행하고 저장 뒤 그 분류를 다시 조회한다.

2026-11-09 사용자 승인 후 공유 Atelier DB에 `20261109052445_visual_work_category_comments.sql`을 적용했다. 새 비공개 댓글 표와 분류 검사 RPC, 첨부 정책을 추가하고 기존 요청 삭제의 첨부 정리 범위를 확장했다. 적용 전 업무·대화·파일 목록은 `docs/backups/visual-work-category-comments-pre-apply-20261109.xlsx`에, 함수 정의와 정책을 포함한 원본은 같은 이름의 JSON에 보관한다.

검증은 `verify:visual-work-category-comments`, `verify:work-request-settings-browser`와 기존 업무 조회·권한·삭제·탐색 검사를 사용한다. 분류 전환과 공통 본문 보존, 모바일, 계정별 댓글·첨부 차단, 답글 범위, 재시도, 재배정, 원래 삭제 흐름을 격리된 가상 데이터로 확인한다.

공유 DB의 인증 역할에서 같은 업무의 배너 댓글 1건·답글 1건과 광고 소재 댓글 1건의 분리 저장·조회를 확인했다. 다른 탭 담당자의 접근, 다른 탭 댓글에 대한 답글, 익명 RPC 호출과 댓글 표 직접 접근을 차단했다. 중복 전송과 기존 업무 조회 호환성을 확인하고 가상 데이터 전부를 롤백했다. 적용 전후 업무·대화·첨부 원본과 기존 정책 및 함수 권한이 일치했다. 비공개 댓글 표는 인증 RPC를 통해 접근한다. ## 새 Visual 요청의 분류별 진행

분류를 선택한 새 Visual 요청은 등록 시 해당 분류의 중간 관리자와 총괄 관리자에게 알린다. 중간 관리자는 자기 분류의 작업자를 바로 지정할 수 있고, 배정받은 작업자에게 알림이 간다. 총괄 확인은 별도로 처리하며 미지정 총괄은 기존 후보 범위에서 확인 또는 첫 총괄 검수 때 정해진다.

작업자는 결과 내용, 링크 또는 비공개 결과 파일을 제출한다. 중간 검수를 통과하면 그 작업자의 해당 분류가 완료되고 총괄 검수가 열린다. 총괄 검수를 통과한 결과와 그 첨부는 같은 저장에서 요청자에게 공개하고 알림을 등록한다. 요청자가 모든 분류를 확인하면 업무 전체가 완료된다.

중간·총괄·요청자의 정식 수정 요청은 각 단계의 횟수를 한 번 올린다. 총괄이 요청자 의견을 중간 관리자에게 전달할 때 총괄 횟수를 0회로 초기화하고, 작업자를 다시 배정할 때는 같은 직원에게 맡겨도 중간 횟수를 0회로 초기화한다. 메인 내용 위에서 요청자·총괄·중간 수정 횟수를 계층으로 확인한다. 작업 진행의 작업 이력에는 배정·제출본·수정 의견·검수 결과가 시간순으로 이어진다.

지정 중간·총괄 관리자와 기존 Visual 업무 관리 담당자는 작업자별 구간과 전체 검수 이력을 읽는다. 현재 작업자는 본인 구간별 제출물·중간 관리자 피드백과 현재 인계 시안을 읽는다. 요청자는 공유된 결과를 확인하거나 수정을 요청한다. 요청자와 분류 관리자가 새로 남긴 공유 댓글은 배정된 작업자도 볼 수 있다. 기존 내부 댓글·첨부와 내부 댓글의 답글은 관리자 범위에서 조회한다.

`20261109210739_visual_workflow_review_rounds.sql`은 총괄 확인과 배정 분리, 수정 묶음, 댓글 및 제출 파일 연결을 검증한 로컬 마이그레이션이다. 공유 DB 적용 전에는 기존 서버 처리 기준이 사용된다.

2026-11-09 `20261109192913_visual_assignment_history_visibility.sql`을 사용자 승인 범위에서 공유 Atelier DB에 적용했다. 운영 이력은 `20261109103827_visual_assignment_history_visibility`다. 기존 수정 횟수는 비공개 표에 옮겼으며, 담당자를 확인할 수 없는 과거 구간은 관리자 화면에 기존 기록으로 표시한다. 적용 전 정의와 이력은 `docs/backups/visual-assignment-history-before-20261109.json`에 보관했다. 적용 전후 요청·이력·알림·설정·직원 원본과 기존 실행 권한을 대조하고, 인증 역할 조회와 익명 접근 차단을 검증했다.

`20261109202708_visual_worker_feedback_counts.sql`로 같은 작업자가 이어서 배정된 경우의 조회를 보완했다. 공유 DB 적용 이력은 `20261109113038_visual_worker_feedback_counts`다. 실제 이미지 업무에서 첫 구간 2회와 현재 구간 0회, 기존 이력 원본과 함수 실행 권한을 대조했다. 이전 함수 정의는 `docs/backups/visual-worker-feedback-counts-before-20261109.sql`에 보관했다.

업무 화면과 종합 알림은 같은 수신 기록을 사용한다. 요청자 알림은 My home의 본인 요청 상세를 열며, 해당 분류와 표시된 버전을 확인한 뒤 읽음을 저장한다. 요청자 확인 대기 표시는 확인 또는 수정 요청을 처리할 때 끝난다.

2026-11-09 사용자 승인 후 `20261109074511_visual_category_workflow.sql`을 공유 Atelier DB에 적용했다. 운영 적용 이력은 `20261109083117_visual_category_workflow`다. 적용 전 함수 정의 4개는 `docs/backups/visual-category-workflow-before-20261109.sql`에 보관했다.

운영 DB에서 인증 역할의 설정·부서 업무·본인 알림 조회, 허용 범위 밖의 이력 조회·단계 변경 차단, 익명 접근 차단과 실시간 연결을 확인했다. 기존 업무·직원·설정 데이터와 기존 정책·함수 권한의 적용 전후가 일치했다. 보안 진단 결과도 일치했다.

새 등록 경로는 서버 지원을 확인한 뒤 사용한다. 이미 접수된 업무, 자체 업무와 분류 없는 요청에는 기존 승인 흐름을 사용한다. 로컬 검증은 `verify:visual-category-workflow`와 `verify:visual-category-workflow-browser`를 실행한다. 사이트 화면 배포는 별도 단계다.

## Visual 총괄 관리자

기존 Visual 업무 관리 담당자가 작업 요청 관리에서 재직 중인 총괄 관리자를 필요한 만큼 설정한다. 총괄이 한 명이면 자동 지정된다. 여러 명이면 업무별로 한 명을 배정하거나, 최종 승인 대기의 미배정 업무를 총괄 관리자가 직접 맡는다. 분류별 중간 관리자는 기존 분류 배정을 사용한다.

요청자 결과 확인 뒤 해당 총괄 관리자가 최종 승인하면 완료된다. Visual 자체 업무도 최종 승인으로 보내며, 반려 사유를 기록하면 업무가 진행 중으로 돌아간다. 기존 완료 건과 다른 부서의 흐름을 보존한다. `20261109062457_visual_work_final_approval.sql`은 공유 DB 승인 전 검수용이며 `verify:visual-work-final-approval`과 `verify:work-request-settings-browser`로 검증한다.
