## 직원과 승인자

- My Schedule 휴가 입력에서 `잔여 부족분 선사용 신청`을 선택하고 사유를 적는다.
- 일반 연차·반차·반반차·외근은 기존 즉시 등록을 유지한다. 선사용 선택 건만 승인 대기다.
- 선사용은 오늘 이후, 현재 확인된 연차 기간 안의 휴가만 가능하다. 미래 기간의 일반 예약과 섞지 않는다.
- 운영지원이 직원별 한도를 먼저 설정한다. 기본 한도 0일이며 임의 기본값/기존 직원 일괄 활성화는 없다.
- 기존 부서 근태 승인자 또는 대체 승인자만 승인한다. 운영지원 조회/관리 권한만으로 승인할 수 없고, 선사용 본인 승인은 금지한다.
- 승인 순간 실제 기본·추가 가용량을 다시 배정하고 부족한 기본분만 선사용 원장에 남긴다. 대기는 차감하지 않는다.
- 직원별 트랜잭션 잠금과 기존 신청 잠금으로 동시 승인 시 한도를 검사한다. 실패는 승인 상태/원장/추가분 배정을 모두 롤백한다.
- 한도를 0으로 바꾸거나 낮추어도 이미 승인된 기록과 부채는 지우지 않는다. 새 승인에 새 한도가 적용된다.

## 잔액과 정산

- 기존 기본 잔액을 실제로 음수로 유지하고 별도로 선사용 승인·취소·이월 분류·정산 사건을 보관한다.
- 기간마다 원래 기본 크레딧/사용량/승인 범위를 구분한다. 확인된 부채만 다음에 발생한 기본분에서 정산한다.
- 기본분 정산은 원래 부족 기간의 크레딧을 늘리고 새 발생 기간의 크레딧을 같은 양 줄인다. 과거 부족분을 두 번 차감하지 않으며 총 가용 잔액을 보존한다.
- 새 발생분이 부족하면 가용 기본분만 정산하고 남은 부채를 유지한다. 오래된 부채부터 처리한다.
- 첫해 같은 기간의 월 발생분은 기존 잔액 증가를 그대로 이용하고, 승인 원장별 월 상환량과 별도 사건을 남겨 이미 갚은 한도가 나중에 재사용/부활하지 않게 한다.
- 추가·생일 연차를 부채 정산용 크레딧으로 전환하지 않는다. 기존 FEFO 배분·기한·부여 취소 재계산을 보존한다.
- 선사용 취소는 기존 휴가 배분을 복원하고 그 건의 승인을 취소 처리한 뒤 정산 차이만 되돌린다. 이미 만료한 기간의 크레딧을 현재 기간에 부활시키지 않는다.
- 반복 cron/조회는 차이 0이면 원장/사건을 다시 만들지 않는다. 기존 한국시간 자정 갱신에 연결하며 새로운 별도 예약을 만들지 않는다.
- 퇴사일·비활성 상태·입사일 불일치·미초기화는 확인 대상으로 표시한다. 급여 자동 공제나 퇴사 금전 정산은 하지 않는다. 기존 시스템에 별도 휴직 상태가 없으므로 휴직에 관한 자동 판정을 새로 추정하지 않는다.

## 기존 엑셀 음수

- 기존 음수는 자동으로 선사용이라고 확정하지 않는다. 기간별 미분류 부족분을 표시한다.
- 운영지원이 엑셀 기준일/근거와 일수를 입력하고 원래 부족 기간을 선택해 이월 분류한다. 현재/과거 확인된 부족분 범위만 가능하며, 한 번 분류한 양을 중복 등록할 수 없다.
- 일부만 확인했다면 나머지를 나중에 추가 분류할 수 있다. 잘못 분류한 경우 `기존 이월 분류 취소`로 이력은 남긴 채 정산을 되돌릴 수 있다.
- 과거 휴가일·신청·당시 승인자·읽음 기록을 만들어내지 않는다. 분류는 기존 잔액을 추가 차감하지 않는다.
- 미분류 부족분이 있으면 신규 선사용 승인을 진행하지 않고 확인을 요청한다.

## 권한과 적용 절차

- 새 표는 `app` 비공개 스키마, RLS 활성화, public/anon/authenticated 직접 접근 회수.
- 관리 RPC는 기존 명부 관리 권한/회사/재직을 확인한다. 본인 조회 RPC는 본인만, 관리 조회는 같은 회사만 반환한다.
- 기존 public 정책과 테이블 ACL을 변경하지 않는다. 기존 신청 원본 불변 검사에 선사용 여부도 포함한다.
- 운영 적용 전 현재 함수 정의/기존 데이터·RLS·ACL 지문과 JSON/XLSX 스냅샷을 저장한다. 다른 AI의 미적용 SQL을 묶어서 실행하지 않는다.
- 2026-11-02 읽기 전용 확인 당시 app 함수 지문: guard_company_leave_request `5a89c9cc332da9d191b8475bc7f0cfa5`, sync_leave_request_balance `ff65ec1b2a5735f7348b808c10e36aed`, refresh_employee_leave `44b0655413955e8355803f425d7e3b79`, reallocate_employee_leave `91c93d23b708129ffd78b14e2db0849b`.
- 적용 승인 시 최신 정의를 다시 대조하고 변경됐으면 현재 기능을 보존해 재검토한다. 적용 후 기존 원본/정책/ACL 해시, RPC 권한, 원장 0건, 기존 클라이언트 일반 신청을 롤백 검증한다. 실제 직원의 선사용 한도/이월 값은 임의 입력하지 않는다.
- 새 사용이 생긴 뒤에는 이전 함수만 단독 복원하거나 표를 삭제하지 않는다. 쓰기를 중지하고 승인·월 상환·기간 간 정산·취소를 대조해 복구한다.
