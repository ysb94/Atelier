# 로그인·출근 IP 관찰

- `test`의 설정 → 접속·출근 IP 기록(`/settings/access-ip`). 사용자가 동일인으로 확인한
  개발자·윤설빈 두 계정만 `access_ip_reviewers`에 지정한다. 직책·관리자 여부·화면 테스트로
  다른 직원의 조회 권한이 생기지 않는다.
- `access-ip-record`는 검증된 로그인 사용자와 게이트웨이의 `CF-Connecting-IP`로만 기록한다.
  본문의 사용자·IP는 받지 않는다. 헤더가 없거나 유효하지 않으면 주소 수집 불가로 남긴다.
- 로그인은 검증된 세션 UUID별 한 번. 새로고침·토큰 갱신·여러 탭의 재전송은 중복 제거한다.
  기존 세션도 기능 적용 후 첫 접속 때 한 번 수집한다. 과거 로그를 소급 생성하지 않는다.
- 출근 버튼 요청마다 별도 기록한다. 출근 성공 여부를 뜻하지 않는다. 기록 요청은 기다리지 않으며
  실패는 `[access-ip]` 경고만 남겨 기존 로그인·승인·출근·퇴근 동작을 막지 않는다.
- 회사 확인/외부 확인/미확인 및 200자 메모는 IP별 수동 표시다. 확인 시각·확인자는 서버에서
  기록한다. 유동 IP이므로 영구 허용 목록이나 출근 차단에 사용하지 않는다.
- DB는 main과 공용이다. IP 관찰 도입은 새 테이블 3개와 그 전용 정책·타임스탬프 트리거만 추가한다.
  기존 프로필·승인·출근 테이블, 함수, 트리거, 정책은 변경하지 않는다.
- 기록 수신 Origin은 test·운영 고정 주소와 로컬 개발 주소를 허용한다. 운영 주소 허용은
  직원 공개 때 IP를 수집할 준비이며, main 화면 코드·브랜치 배포는 별도 승인으로 진행한다.
  로그인 이후 브라우저가 보내는 관찰 기록이므로 보안 감사 전체를 대체하지 않는다.
- 적용 완료: `20261022094409_access_ip_records.sql` 및 새 Edge Function `access-ip-record`.
  DB는 추가 방식이므로 앱 복구 시 해당 화면·수집 호출을 이전 버전으로 되돌리면 된다.
  수집 중지는 새 Edge Function만 비활성화한다. 기존 데이터 삭제나 기존 인증 설정 변경은 필요 없다.
- 검증: `npm run verify:access-ip`(임시 PostgreSQL RLS·중복·원본 헤더),
  `npm run verify:access-ip-browser`(실제 로그인/출근 훅과 화면, 외부 연결 차단),
  `verify:auth-recovery-browser`, `verify:my-attendance`, `verify:diagnostics`, 빌드.
  배포 서버에서도 개발자 로그인 기록 저장·중복 제거·본인 조회·익명 차단·main 요청 제외를 확인했다.
  적용 전후 프로필 전체 해시, 사용자 수, 출근 기록 수와 기존 출근 함수·프로필 정책 해시가 동일하다.
- 윤설빈의 개발자 권한은 기존 `permission_grants`에 개발자와 같은 코드·범위로 추가한다.
  전환 전 legacy 로그인에서는 이 계정에 한해 명시적 지정도 합친다. 전체 권한 전환 스위치는 유지한다.
  프로필·승인·부서·직책은 수정하지 않는다. 기존 지정·다른 사용자의 권한도 지우지 않는다.
  `20261022100529_developer_account_delegate.sql`은 서버의 개발자/관리/조직/공모전 판정에
  승인된 동일인 UUID를 추가하고 기존 브랜드 책임 권한과 직원 전환 허용도 맞춘다.
  기존 함수의 실행 권한은 넓히지 않는다. `verify:developer-delegate`가 코드·범위 일치와 격리를 검증한다.
