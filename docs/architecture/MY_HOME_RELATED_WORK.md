# My home 내 업무 통합 목록

기존 ToDo / ing / feedback / done 아래에 `피드백 온 업무`와 `내가 지시한 업무`를 같은 너비로 표시한다. 작은 화면은 세로 배치하며, 빈 목록도 유지한다. 기존 개인 카드의 검토 요청·배정 목록은 두 영역으로 통합했다.

## 기준과 상세 연결

- 개인 카드의 현재 `reviewer_id`와 `feedback` 상태, 부서 업무의 기존 관리자 검수·요청자 결과 확인, Visual의 `visual_workflow_targets` 중 검토·결과 확인·수정 의견 전달 단계를 피드백 대기로 표시한다. 배정·접수·작업 시작 안내는 피드백 대기에 포함하지 않는다. 읽음과 처리 완료는 별개다.
- 지시한 업무는 개인 카드의 현재 관리 주체(`handover_owner_id`, 없으면 `created_by`)와 타인 담당자, 부서 요청자·주 담당 배정자·분류 배정자·Visual 작업자 지정 이력의 실제 UUID로 판정한다. 현재 조회 권한을 함께 확인하며 이름으로 추정하지 않는다. 서버에 없는 과거 배정 이력은 재구성하지 않는다.
- 개인 카드 혼자 할 일, 혼자 수행하는 자체 업무, 초안과 삭제는 제외한다. 외부 요청은 담당자 미배정도 포함한다. 완료·취소·반려는 지시한 업무에 계속 표시한다. 중국 작업지시서·자재·단가 요청은 이번 통합 대상이 아니다.
- 출처와 업무 ID를 고유 키로 사용한다. Visual 여러 분류의 검토는 한 업무 아래 묶는다. 각 행에는 제목·메뉴·요청자·담당자·상태·최근 활동 시각을 표시한다.
- 개인 피드백 알림 ID는 현재 카드 revision과 일치하는 미해결 알림만 반환한다. 기존 `personalWorkFeedback` 상세 연결에서 내용을 정상 표시한 뒤 같은 알림의 읽음을 저장한다. Visual 요청자 검토는 기존 `visualReview` 상세, 관리자와 분류 검토는 기존 부서 상세로 연결한다. 일반 요청자 결과 확인과 보낸 요청은 기존 `part=work&workOwner=...&requestId=...`를 사용한다.

## API와 갱신

`list_my_home_related_work(p_view, p_before_at, p_before_key)`는 `feedback` 또는 `issued`를 받는다. 로그인 본인의 회사와 기존 업무 접근·처리 권한을 확인한다. public 래퍼는 invoker이고, private 카드 조회를 위한 app 함수는 고정 빈 search_path와 명시적 본인·회사 조건을 사용한다. 익명 실행을 허용하지 않는다. 기존 함수·표·RLS와 업무 원본을 수정하지 않는다.

응답은 `items`, `total`, `nextCursor`다. 시각과 출처별 ID를 함께 비교해 최근 활동순으로 20건을 반환한다. 목록에는 본문·첨부·대화·업무 이력을 싣지 않는다. 원본 개인 카드 조회는 기존 4칸과 상세용으로 유지한다.

활성 내 업무 화면에서 30초마다 조회하고 개인 카드·피드백 알림·Visual 알림·부서 업무의 기존 쿼리 성공/무효화 및 온라인 복귀에서 목록을 갱신한다. 계정별 쿼리 키를 사용하고 숨겨진 화면에서는 추가 조회를 중단한다. 실패 시 기존 목록과 재시도를 표시한다. RPC가 아직 없으면 기존 개인 카드만 표시하고 부서 업무 연결 대기 상태를 명시한다.

## 검증과 적용

- Node 22에서 `npm run verify:my-home-related-work`로 격리 PGlite와 운영 네트워크를 차단한 로컬 브라우저를 검증한다. 빌드된 CSS가 필요하므로 먼저 `npm run build`를 실행한다.
- DB 검증: 기존 함수 보존, 본인/타인/다른 회사/비활성/익명, 인계, 이름 중복, 지시자 중복, 전체 종료 상태, Visual 현재 수신자와 분류 묶음, 읽은 미처리, 오래된 revision, 20건 커서 경계를 검사한다.
- 브라우저 검증: 실제 보드·상세·읽음 훅으로 네 칸 유지, 반응형 두 칸·긴 제목, 페이지 추가, 분류 상세 링크, 상세 열람 후 읽음, 승인 후 양쪽 동기화, 실패 재시도, 숨김, 기존 서버 대체 표시, 계정 전환을 확인한다.
- 기존 `verify:visual-category-workflow`는 새 통합 조회 코드를 실행하기 전 `20261118102144_visual_category_comment_participants.sql`의 기존 함수 문자열 검사에서 실패했다. 이 검증의 입력 파일들은 HEAD와 같으며 이번 변경에서 수정하지 않았다. 새 통합 목록의 Visual 현재 담당·분류 묶음·결과 확인·지정 총괄 권한은 별도 격리 DB 검증을 통과했다.
- `20261126115127_my_home_related_work.sql`은 **로컬 구현이며 공유 DB 미적용**이다. 기존 표나 권한 경계를 넓히지 않는 조회 API 두 함수만 추가한다. 적용 승인 후에는 기존 함수/데이터/권한 보존과 실제 인증 역할별 읽기 전용 조회를 확인한다. 되돌릴 때는 새 API 실행 권한만 회수하며 업무 자료는 삭제하지 않는다. 운영 화면 배포는 별도다.
