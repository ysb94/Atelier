## 사용 순서

1. 직원은 My home → My Schedule → 주말·공휴일 근무에서 예정 근무를 등록한다.
   기존 외근·승인된 야근 신청·출퇴근이 있으면 같은 직원·날짜의 참고 항목으로 자동 표시한다.
2. 종료 후 직원이 **휴게시간을 제외한 실제 근무 구간**을 제출한다.
   예정 시간이나 퇴근 버튼 시각을 실제 근무시간으로 자동 복사하지 않는다.
   자정을 넘으면 날짜별로 나눈다. 사무실·외근이 겹쳐도 하루 한 건으로 관리한다.
3. 기존 부서 야근 승인자·대체 승인자가 My home → 승인할 신청에서 실제 구간을 확인하거나
   보완 요청한다. 자기 건은 확인할 수 없다. 운영지원 권한만으로 시간 확인을 대신하지 않는다.
4. 운영지원 → 근태 → 외근 관리 오른쪽 **주말·공휴일 근무 관리**에서 확인된 시간을 정산한다.
   같은 직원의 여러 날짜·월을 묶을 수 있다. 금액이나 휴가를 확정하지 않은 시간은 계속 보관한다.
5. 수당은 확인한 통상시급·지급 예정 월·사유로 지급 예정액을 확정한다. 실제 지급 후 날짜와
   확인을 별도로 기록한다. 급여 이체나 외부 급여 시스템 전송은 하지 않는다.
6. 보상휴가는 실제 체결한 근로자대표 서면합의의 기준명·체결일·적용 확인을 등록해야 열린다.
   현재 사용자는 미체결이라고 답했으므로 초기 기준은 비어 있고 휴가 지급은 서버에서도 잠긴다.
   반반차 0.25일·반차 0.5일·연차 1일 또는 .25일 단위 합계와 사용기한을 선택한다.
   기존 추가 연차 원장으로 지급하고, 사용·취소·기한은 기존 FEFO 절차를 따른다.

## 시간과 보상 기준

- 실제 분과 가산 보상 시간을 별도 보관한다. 최소 단위는 30초로, 1분 × 1.5의 소수분도 버리지 않는다.
- 토요일: 회사가 요청한 1.5배 기준. 일요일·공휴일: 하루 실제 8시간까지 1.5배, 초과분 2배.
  22:00~06:00 실제 구간은 0.5배를 더한다. 휴게 구간은 실제 시간에서 빠진다.
- 토요일을 법정 휴일이라고 일괄 판단한 것은 아니다. 현재 회사 기준에 따른 별도 분류이며,
  다른 근무제·휴일 지정이 필요하면 기준을 먼저 변경해야 한다.
- 하루 휴가 = 8시간. 선택한 지급 단위로 환산한 뒤 **남은 시간은 미정산 원장에 유지**한다.
  예: 토요일 실제 2시간 → 가산 3시간 → 반반차 2시간 지급 → 잔여 1시간 보관.
- 수당은 가산 보상 시간 × 입력한 통상시급, 원 미만 올림. 통상시급을 연봉이나 고정OT에서 추정하지 않는다.
- 서버의 기존 공휴일 달력을 사용하고 미등록 연도의 처리는 막는다.
- 근거: [근로기준법 제56조](https://www.law.go.kr/법령/근로기준법/제56조),
  [제57조](https://www.law.go.kr/법령/근로기준법/제57조).

## 저장·권한·중복 방지

추가 SQL: `20261104081247_holiday_work_settlement.sql`.
`app.holiday_work_days`는 회사·직원·날짜 고유 키, 실제 구간·제출 버전·승인 근거를 보관한다.
새 전용 이력·보상·시간 배분·알림·서면합의 기준 표는 비공개 스키마와 RLS를 사용한다.
공개 RPC `holiday_work`는 invoker이고 내부 API는 매번 본인/현재 부서 승인자/기존 운영지원 권한을 검사한다.
일반 클라이언트는 원장을 직접 읽거나 쓰지 못한다. 회사가 다른 원본을 연결하지 않는다.

직원별 기존 advisory lock을 공유하고 수정 버전으로 경합을 막는다. 정산 UUID와 요청 해시가 같으면
재시도로 중복 부여하지 않는다. 수당·휴가가 소비한 시간을 동일 원장에서 차감하고 잔여만 처리한다.
확인 후 연결된 신청 원본과 보상휴가 원본을 임의 변경해 정산과 분리할 수 없다.
잘못 확인·확정한 이력을 덮어쓰는 기능은 제공하지 않는다. 추후 취소·정산 정정은 별도 원장 절차가 필요하다.

주말·공휴일 근무가 조금이라도 포함된 외근은 **건 전체**를 주말·공휴일 근무 관리에서 후처리한다.
외근 관리에는 건 전체 후처리 링크만 표시한다. 해당 건을 선택하면 평일 기록과 전체 기간의
주말·공휴일 실제 시간·보상을 같은 화면에서 처리한다. 월을 넘겨도 해당 건 전체를 조회한다.
평일 추가 근무는 기존 야근 누적/휴가/추가 근무 없음 절차와 계산 기준을 유지한다.
주말·공휴일에만 해당 가산 기준을 적용하며 평일 전체 시간에 1.5배를 적용하지 않는다.
평일 전용 외근과 기존 반복 평일 외근은 기존 외근 관리에서 처리한다. 자정에 끝나면 다음 날은 포함하지 않는다.
구버전 화면에서도 주말 포함 외근의 평일분까지 이전 후처리 경로로 저장하지 못하게 한다.
새 공용 RPC가 기존 운영지원 권한과 원본 외근을 검사한 뒤 내부 문맥을 한 트랜잭션에서 설정·복구해
기존 평일 저장 함수를 호출한다. 주말분의 야근 중복 누적과 서면합의 전 휴가 지급은 계속 차단한다.
이미 저장된 외근·야근 보상은 수정하지 않으며, 해당 날짜는 기존 이력으로 표시하고 다시 정산하지 않는다.
기존 연차 기본 잔액·출퇴근 시각·고정OT 집계 함수·사용자/회사/부서 권한은 변경하지 않는다.
과거 미정산 출퇴근·외근은 조회하되 조회만으로 신청·알림을 소급 생성하지 않는다.

계정 변경 시 캐시 키와 입력·선택을 분리하며 비활성 화면은 추가 조회와 읽음을 멈춘다.
새 업무는 기존 workflow 진단으로 검사·DB 처리·갱신 실패를 구분하고 식별값·입력 원문은 기록하지 않는다.
