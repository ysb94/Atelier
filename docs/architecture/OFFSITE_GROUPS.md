# 단체 외근 등록

## 동작과 권한

- 같은 회사 활성 직원 누구나 외근 신청에서 참여자를 선택한다. 본인이 기본 선택되며 해제할 수 있다. 선택하지 않으면 기존 개인 신청 흐름을 사용한다.
- 서버가 참여자 전체를 검증하고 개인 신청을 원자적으로 생성한다. 일정 충돌·잘못된 참여자가 있으면 전부 롤백한다. 동일 등록 번호 재시도는 동일 내용을 반환하며 다른 내용은 차단한다.
- 생성 이후 개인 신청의 취소·사무실 복귀는 본인만 한다. 등록자는 본인이 등록한 묶음의 참여자 이름과 외근 상태만 조회한다. 참여자는 본인 상태만 조회한다.
- 당일 출근 기준은 오늘/미래 시작일의 본인 외근 상세에서 변경·해제한다. 같은 날 유효한 외근에 함께 적용하며 변경 전후를 비공개 이력에 기록한다. 원본 출퇴근과 기존 지각 사유서는 수정하지 않는다. 후처리가 끝난 외근은 기준을 변경하지 않는다.

## 서버와 알림

- `register_offsite_group`, `my_offsite_groups`, `set_my_offsite_start`는 authenticated 전용 invoker 진입점이다. 내부 함수에서 재직·회사·본인 권한을 확인한다.
- `offsite_groups`와 nullable `company_leave_requests.offsite_group_id`로 연결한다. 기존 행은 변경하지 않는다. 기존 신청 RLS를 확대하지 않고 비공개 트랜잭션 문맥에서만 대리 생성과 기준 수정을 허용한다. 직원 잠금은 정렬해 획득한다.
- 알림 키는 개인 신청별 `offsite-group:{requestId}`다. 기존 서버 알림 조회·읽음 API를 사용하며 승인 대기 숫자는 만들지 않는다. 본인 신청 상세에 접근해 실제 표시된 경우 읽음 처리한다. 취소 상태는 현재 업무 알림에서 제외된다.
- 외근 자동 출퇴근·야근 실제 입력·외근 후처리는 기존 개인 신청을 사용한다. 단체 등록만으로 야근 실적이나 보상을 추가 생성하지 않는다.

## 검증과 적용

- `npm run verify:offsite-groups`: 격리 DB에서 원자 저장·재시도·충돌·개인 권한·출근 기준·비공개 이력·알림을 검증하고 실제 신청 컴포넌트로 참여자 선택·충돌·재시도를 확인한다. 브라우저 검증은 외부 API를 차단한다.
- 기존 출근 기준·연속 외근·종합 알림 검증도 수행한다. 격리 DB는 기존 PGlite 도구를 사용하며 공유 Supabase와 별개 테스트 프로젝트를 생성하지 않는다. 실제 PostgreSQL 다중 세션 경합은 공유 DB 승인 후 롤백 검증할 항목이다.
- 마이그레이션: `20261104033803_offsite_group_registration.sql`. **2026-11-04 12:38 KST 사용자 승인 후 공유 DB 적용 완료**. 기존 11개 영역의 원본과 기존 정책·함수 실행 권한을 DB 내부에서 비교해 보존했다. 익명 차단·비공개 문맥 접근 차단과 보안 점검을 확인했다. 신규 WARN/ERROR는 없고 비공개 표 2개의 기본 접근 거부 INFO만 추가됐다.
- 공유 DB의 관련 함수·실행 권한 복구본을 `docs/backups/offsite-groups-functions-before-20261104.json`에 보관한다. 적용 직전에 스키마·정책 스냅샷을 추가하고 기존 원본 보존을 DB 내부에서 비교한다. 사용자 승인 후 호환 마이그레이션을 적용하고 실제 인증 역할·동시 처리·읽음 연동을 검증한다.

- 실제 공유 DB에 합성 Auth 사용자·근태를 생성하고 롤백하는 검증 및 모든 활성 직원 역할의 알림 조회 검증은 자동 승인 심사에서 승인 범위 부족으로 거절되어 실행하지 않았다. 해당 실DB 검증은 별도 사용자 승인 전까지 미검증으로 남긴다. 로컬 격리 DB·브라우저 검증 결과와 구분한다.
