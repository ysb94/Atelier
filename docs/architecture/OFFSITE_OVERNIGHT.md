# 다음 날 종료 외근

후속 로컬 변경: [연속 외근·후처리](OFFSITE_SETTLEMENT.md)에서 24시간 상한 제거와 보상 흐름을 준비했다. 해당 추가 SQL은 운영 DB 미적용이며, 아래 24시간 설명은 기존 운영 저장 방식의 기준이다.

2026-11-03 공유 운영 DB 적용·검증 완료. main 화면 배포는 미실시.

- My Schedule 외근 입력은 시작 날짜·시각과 실제 종료 날짜·시각을 받는다. ‘다음 날 종료’ 체크박스는 없다. 예: 시작 11/4 09:00, 종료 11/5 03:00 입력 시 저장용 복사본만 `from_date=to_date=11/4`, `end_next_day=true`로 자동 변환한다. 화면의 종료 날짜는 유지한다. 한 건 최대 24시간이라는 기존 DB 제약을 유지하고 긴 구간을 여러 날 반복 외근으로 조용히 바꾸지 않는다. 기존에 저장된 여러 날 반복 외근 원본과 조회는 변경하지 않는다.
- 외근은 기존처럼 승인 없이 등록한다. 연차 차감·야근 승인·실제 야근 누적 기준을 변경하지 않는다. 다음 날 종료 외근만으로 야근이나 보상 휴가를 생성하지 않는다.
- 새벽 퇴근은 시작일의 출퇴근 한 건에 저장한다. 자동 처리·상태 조회·사무실 복귀·조기 수동 퇴근에서 전날 근무일을 유지한다. 기존 수동 출퇴근과 취소 시 원본 보존 규칙을 유지한다.
- 자정 이후 계속 근무 중인 외근은 새 날짜 출근/전날 퇴근 미등록 창으로 막지 않는다. 서버 상태와 실제 미퇴근 원본이 모두 있는 경우만 이어서 근무한다. 근무를 끝낸 뒤에는 정상적으로 새 날짜 출근을 안내한다.
- 회의 시간표는 시작일 09:00~24:00, 다음 날 00:00~03:00으로 외근 범위를 표시한다. 회사·호스트·멤버 조회 권한 검사는 기존대로 유지한다.
- 기존 `end_next_day` 필드만 사용하며 기존 행·잔액·RLS·실행 권한을 재작성하지 않는다. 마이그레이션은 외근 제약 한 분기와 관련 내부 함수 7개만 보완한다. 기존 자동 처리 활성화 시각·잠금 순서·2초/100ms 잠금 제한·중복 방지는 유지한다.
- `20261103081826_offsite_overnight_schedule.sql` 적용 전에는 기존 RPC에 `overnightSupported`가 없으므로 다음 날 종료 외근 저장을 차단하고 DB 적용 대기를 안내한다. 이전 코드도 추가 필드를 무시하고 기존 외근을 사용할 수 있다.
- `npm run verify:offsite-overnight`: 실제 My Schedule 입력 화면, 자정 이후 실제 출퇴근 훅, 계산 검증, 기존 외근 DB 회귀와 원본/정책/함수 실행 권한 비교. 격리 DB에서만 서버 시계를 대체해 자정·03시·복귀·수동 퇴근·회의 불가 구간을 확인한다. 운영 직원 시험 기록을 생성하지 않는다.
- 실제 야근 입력 마이그레이션 `20261103081759_overtime_actual_reports.sql`도 함께 적용했다. 운영 함수 대조에서 기존 2초 출근 잠금 제한·공가 종일 표시·회의 제외 멤버 필터를 확인해 모두 보존했다. 데이터/권한은 DB 내부에서만 비교하고 폐기했으며, 실제 직원 권한 검증은 롤백했다. 매분 자동 처리 작업의 적용 후 성공도 확인했다.

- 2026-11-03 입력 UX 보완은 `offsite-form.ts`의 UI→기존 저장 형식 변환과 `OffsiteDateTimeFields`만 사용한다. DB 마이그레이션·권한·원본 데이터 수정은 없다. 동일 날짜, 다음 날, 월말·연말·윤일·24시간 경계와 잘못된 시간 범위, 기존 원본 불변을 검증한다. 브라우저에서는 실제 날짜 선택으로 다음 날 자동 판정과 저장 payload를 검증한다.
