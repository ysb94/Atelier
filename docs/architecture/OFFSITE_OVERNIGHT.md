# 다음 날 종료 외근

2026-11-03 로컬 구현·격리 검증. 운영 DB **미적용**, main 배포 미실시.

- My Schedule 외근 입력의 ‘다음 날 종료’를 선택하면 시작일 한 건으로 등록한다. 예: 11/4 09:00 → 11/5 03:00은 `from_date=to_date=11/4`, `end_next_day=true`다. 종료일 반복 입력과 혼용하지 않으며 최대 24시간을 허용한다. 같은 날·여러 날 반복 외근은 기존 방식을 유지한다.
- 외근은 기존처럼 승인 없이 등록한다. 연차 차감·야근 승인·실제 야근 누적 기준을 변경하지 않는다. 다음 날 종료 외근만으로 야근이나 보상 휴가를 생성하지 않는다.
- 새벽 퇴근은 시작일의 출퇴근 한 건에 저장한다. 자동 처리·상태 조회·사무실 복귀·조기 수동 퇴근에서 전날 근무일을 유지한다. 기존 수동 출퇴근과 취소 시 원본 보존 규칙을 유지한다.
- 자정 이후 계속 근무 중인 외근은 새 날짜 출근/전날 퇴근 미등록 창으로 막지 않는다. 서버 상태와 실제 미퇴근 원본이 모두 있는 경우만 이어서 근무한다. 근무를 끝낸 뒤에는 정상적으로 새 날짜 출근을 안내한다.
- 회의 시간표는 시작일 09:00~24:00, 다음 날 00:00~03:00으로 외근 범위를 표시한다. 회사·호스트·멤버 조회 권한 검사는 기존대로 유지한다.
- 기존 `end_next_day` 필드만 사용하며 기존 행·잔액·RLS·실행 권한을 재작성하지 않는다. 마이그레이션은 외근 제약 한 분기와 관련 내부 함수 7개만 보완한다. 기존 자동 처리 활성화 시각·잠금 순서·2초/100ms 잠금 제한·중복 방지는 유지한다.
- `20261103075546_offsite_overnight_schedule.sql` 적용 전에는 기존 RPC에 `overnightSupported`가 없으므로 다음 날 종료 외근 저장을 차단하고 DB 적용 대기를 안내한다. 이전 코드도 추가 필드를 무시하고 기존 외근을 사용할 수 있다.
- `npm run verify:offsite-overnight`: 실제 My Schedule 입력 화면, 자정 이후 실제 출퇴근 훅, 계산 검증, 기존 외근 DB 회귀와 원본/정책/함수 실행 권한 비교. 격리 DB에서만 서버 시계를 대체해 자정·03시·복귀·수동 퇴근·회의 불가 구간을 확인한다. 운영 직원 시험 기록을 생성하지 않는다.
- 직전 실제 야근 입력 마이그레이션 `20261103074047_overtime_actual_reports.sql`도 별도 승인 대기이며 이번 작업으로 적용하지 않았다.
