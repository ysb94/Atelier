# 회차별 참석자와 결과 공유

상태: 로컬 구현·격리 검증. 공유 운영 DB 미적용, main 미배포.

## 동작

- 호스트는 일정 확정 전·후에 회차 멤버 관리에서 참석 / 결과만 공유 / 제외를 지정한다. 기존 응답은 유지하며 추가 참석자만 초대한다. 선택한 직원의 기존 일정 충돌을 보여주며 회의 시간을 자동 변경하지 않는다.
- 다음 회차를 새로 만들 때 직전 회차 명단을 복사한다. 제외자는 승계하지 않는다. 기존 회차·이미 만든 다른 회차는 변경하지 않는다. 수동 확정의 불참 제외는 영구 역할 변경과 별개다.
- 결과 공유자는 기본 일정 정보와 본인이 공유받은 결과만 본다. 참석 응답·일정 점유·사전 알림·본문·준비 자료·파일 받기·단체채팅에서는 제외한다. 현재 명단에서 완전히 제외해도 기존 공유 결과 수신 기록을 유지한다.
- 호스트의 결과 초안 저장과 결과 공유를 분리한다. 새 회의의 결과 초안은 직원이 직접 조회할 수 없는 별도 저장소에 보관한다. 공개 버전은 불변이며 재공유 전에는 이전 버전을 유지한다. 같은 결과의 재공유·재시도는 중복 알림을 만들지 않는다.
- 결과 알림과 참석 해제 안내는 `meeting_round_notices`를 종합 알림·회의 탭에서 함께 사용한다. 화면에 표시한 정확한 결과 버전만 읽는다. 결과 공유 알림은 처리 대기 건수에 포함하지 않는다. 결과 공유·멤버 변경으로 오래된 호스트 응답 안내를 현재 처리 대상으로 재사용하지 않는다.
- 단체채팅은 가장 최근 공개된 회차의 참석자·호스트만 유지한다. 다음 회차 초안은 현재 채팅에 영향을 주지 않는다. 메시지 원본은 삭제하지 않는다.

## 저장과 권한

- 추가 마이그레이션: `20261104025826_meeting_round_roles_results.sql`.
- 기존 회의·회차·초대·읽음·자료 행은 마이그레이션에서 일괄 수정하지 않는다. 기존 명단은 회차별 명단을 처음 수정할 때 현재 저장값으로 고정한다. 없는 과거 명단을 추정하지 않는다. 완료 결과 알림을 소급 생성하지 않는다.
- `app`의 회차 명단·변경 이력·결과 초안·공유 버전은 직원 직접 조회를 금지한다. 새 공개 알림 표는 본인·동일 회사만 조회한다. 새 공개 RPC는 invoker이며 실제 권한 검사는 비공개 구현에서 한다.
- 회차별 명단 API는 호스트·회사·활성 직원·revision을 검사한다. 기존 예약 충돌·점심시간·회차 제약·파일 RLS를 재사용하고, 역할에 따라 원본 회차와 Storage 접근을 제한한다. 기존 관리자 권한은 유지한다.
- 구 화면에서 새 역할을 모르고 회의 전체 명단을 덮어쓰려 하면 명단 관리 안내로 거절한다. 기존 공개 목록의 기본 정보 노출 범위는 유지한다.
- 적용 전 실제 설치 함수와 추가 마이그레이션의 교체 지점이 일치해야 한다. 지점이 다르면 적용을 중단한다. 새 공개 알림 표만 Realtime에 추가하며 기존 publication 설정은 바꾸지 않는다.

## 검증

- `node scripts/verify-meetings-db.mjs`: 기존 회의 검증에 회차별 명단 DB 검증을 추가했다. 기존 데이터·정책·함수 실행 권한의 전후 비교, 추가 참석자 응답, 결과 공유자 접근 거부, 초안 비공개, 재공유·정확한 버전 읽음, 1~4차 승계·제외, 수동 확정·채팅 복귀를 검사한다.
- `node scripts/verify-page-preview-browser.mjs --round-roles-only`: 운영 API를 차단한 화면 검증. 명단 변경·직원 추가·실패 후 재시도·결과 공유·결과만 공유받는 직원 화면을 검사한다.
- `npx tsx src/features/meetings/meeting-round-members.verify.ts`: 레거시 명단·명시적 빈 명단·승계·회차 격리·중복 계산.
- 기존 회의 화면, My home 알림, 시작 전 알림·My Schedule 관련 검증과 Node 22 빌드·진단·구조도 검증을 함께 수행한다. 운영 DB 실검증은 적용 승인 후 별도 기록한다.
