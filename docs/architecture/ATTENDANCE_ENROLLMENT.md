# 가입 승인에 따른 근태 집계 시작일

## 범위

입사일·계정·출퇴근·휴가 원본·연차 잔액·기존 권한은 변경하지 않는다.
본사 근태 명부에 별도의 승인 기준일을 연결하여 지각·결근·미기록과 달력·내보내기의
집계 범위를 일치시킨다. 사이트 도입일(2026-11-02), 입사일, 본사 관리 전환일,
승인 기준 시작일 중 가장 늦은 날짜를 사용한다. 원본 기록은 삭제하지 않는다.

## 승인 기준

- 한국 시간으로 승인일의 실제 출근 기준을 조회한다. 개인별·부서별 기준과 기존 외근 기준을 재사용한다.
- 출근 기준 시각 이전 또는 정확히 같은 시각에 승인되면 그날부터 집계한다.
- 기준 시각이 지난 뒤 승인되거나 기준이 미설정이면 다음 근무일부터 집계한다.
- 토요일·일요일·공휴일을 기존 서버 국가 달력으로 건너뛴다. 연도 자료가 없으면
  계정 승인을 막지 않고, 근태 조회에서 오류를 표시해 잘못된 지각·결근 계산을 차단한다.
- 도입일 전에 승인된 기존 직원과 승인일이 없는 기존 활성 계정은 기존 도입일 기준을 유지한다.
- `app.attendance_enrollments`에 최초 승인 시각과 당시 출근 기준을 보관한다.
  이후 출근시간·승인일 편집·비활성/재활성화로 최초 기준을 덮어쓰지 않는다.
- 기존 활성·비활성 계정은 현재 승인 이력으로 새 표에 기준만 추가한다.
  프로필의 입사일·승인일과 원본 근태는 수정하지 않는다.

## 연결·권한

신규 `profiles_attendance_enrollment` AFTER 트리거가 기존 승인 저장과 같은 트랜잭션에서
기준을 기록한다. 기존 승인 API와 다른 프로필 트리거는 교체하지 않는다.
기존 직원 목록 API를 재사용하는 `list_attendance_enrollments`는 현재 활성 계정의 회사와
열람 가능한 명부에 한해 직원 ID·집계 시작일만 반환한다. 원본 승인 시각·출근 기준은 노출하지 않는다.
원본 프로필·명부 함수·RLS·permission_grants의 기존 권한을 확대하지 않는다.

새 원본 표는 private `app` 스키마에 두고 모든 클라이언트 역할의 직접 접근과 내부 함수 실행을 막는다.
본사 근태 화면만 공통 조회 캐시를 사용하고 활성 화면에서 최대 30초 간격으로 보완한다.
다른 회사·다른 계정의 캐시를 공유하지 않는다. 실패·누락·서버 미적용 때는 결근을 계산하지 않고
조회 오류와 재시도를 표시한다. 새 승인자가 명부에 나타나면 명부 구성에 따른 조회 키로 시작일을
다시 조회한다. 같은 명부를 보는 여러 화면은 같은 조회를 공유한다.
업무 알림·새 승인 권한·소급 지각 사유서 요청을 만들지 않는다.
도입일 이후 승인된 계정의 본인 출근 기능도 같은 시작일을 확인한다. 시작일 전에는
로그인 출근 강제창·지각 사유서 흐름을 열거나 출근을 저장하지 않는다. 휴가·업무 권한은
그대로 유지하고, 공통 한국 날짜가 바뀌면 시작일 조건을 다시 평가한다.

## 검증

- `npm run verify:attendance-enrollment`: 격리 DB에서 기존 원본/권한 보존, 오전·정각·초과 승인,
  미설정, 주말·공휴일, 향후 승인 트리거, 재승인·출근시간 변경, 익명·미승인·타사 차단을 확인한다.
- 실제 명부 hook·지각/결근 패널·달력·월별 계산으로 승인 전 제외, 이후 정상 집계,
  조회 공유·실패/재시도·계정 전환과 입력 원본 보존을 브라우저에서 확인한다.
- Node 22 빌드, 관련 근태·조회 제한시간·업무 진단·구조도 검증을 수행한다.

## 적용 상태

사용자 명시 승인 후 공유 운영 DB에 `20261105094711_attendance_approval_tracking_start`를 적용했다.
서버가 부여한 실제 마이그레이션 버전과 로컬 SQL 파일 이름을 일치시켰다.

실제 대상 계정은 입사일 2026-11-03, 승인 2026-11-05 16:11:26(한국 시간)을 보존한 채
집계 시작일 2026-11-06으로 조회된다. 승인 당시 출근 기준 미설정으로 다음 근무일을 사용한다.
프로필 39행·출퇴근 108행·휴가 신청 52행·직원 명부 26행·권한 지정 30행의 적용 전후 지문이
일치했다. 기존 정책·관련 함수 정의/ACL·기존 프로필 트리거·원본 표 RLS/ACL도 일치했다.
새 메타데이터는 39계정에 추가했으며 기존 직원 값을 덮어쓰지 않았다.

실제 직원의 authenticated 역할을 READ ONLY 트랜잭션에서 검사했고,
대상 시작일·최소 반환 필드·미승인 차단·원본 표 직접 접근 차단을 확인했다.
운영 REST에서도 새 RPC가 등록되고 익명 요청은 401/42501로 거절된다.
적용 후 보안 점검에 새 지적은 없었다. 검증용 실제 직원·출퇴근·휴가 기록을 만들지 않았다.

Node 22 빌드, 격리 DB·브라우저·월별 근태·요청 제한시간·업무 진단·구조도 검증을 통과했다.
main 화면 배포는 하지 않았다. 기존 배포 화면은 새 조회 경로를 포함한 코드 반영이 필요하다.
