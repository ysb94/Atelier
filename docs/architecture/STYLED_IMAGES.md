# 연출컷 API 시험 생성

2026-09-15 기준. `디자인 → 연출 컷 제작 → 연출컷 스튜디오`에서 모델을 직접 선택한다.

## 연결

- `styled-image` Edge Function을 사용한다. 기존 송장/회사 도우미용 `ai-gateway`와 분리한다.
- 기존 서버 Secret `OPENAI_API_KEY`, `GEMINI_API_KEY`를 재사용한다. 키를 브라우저·DB에 복사하지 않는다.
- GPT Image 2, GPT Image 2.5 Flare, GPT Image 2.5 Sunburst, Nano Banana Pro (`gemini-3-pro-image`)를 허용한다.
- `models`는 각 제공자의 모델 메타데이터를 조회한다. 키의 모델 접근 여부만 확인하며 이미지 생성이나 청구 성공을 보장하지 않는다.
- OpenAI는 Images Edit API의 multipart 원본 이미지 업로드를 사용한다. 품질은 Low·Medium·High, 2.5 계열은 XHigh·Max도 선택한다. 기본은 고해상도·High, 출력은 PNG이며 지정 비율에 맞는 16px 단위 크기를 보낸다.
- Google은 Interactions API에 원본 이미지와 역할을 보내고 1K·2K·4K **JPEG** 이미지를 선택한다(기본 2K). 나노바나나 Pro에 `response_format.mime_type=image/png`를 보내면 실제 생성 API가 400으로 거부한다. `store: false`이며 최종 `model_output` 이미지만 사용하고 반환된 MIME에 맞춰 다운로드 확장자를 정한다.

## 권한과 데이터

- JWT 검증을 켜고 함수 안에서도 `auth.getUser`로 인증한다.
- 승인된 E&J 회사 직원 중 관리자 또는 디자인 업무 역량이 있는 직원만 호출한다. 사용자 메타데이터를 권한 근거로 쓰지 않는다.
- DB·Storage에는 쓰지 않는다. **시험 화면의 사진과 결과는 메모리에만 유지한다.** 새로고침/탭 닫기 전에 다운로드해야 한다. 업무 원본을 IndexedDB에 새로 저장하지 않는다.
- API 없는 단독 HTML 미리보기는 기존 브라우저 저장 방식과 가상 요청 체험을 유지한다.
- 서버 로그는 사용자 ID, 모델, 장수, 상태, 소요 시간만 기록한다. 원본 이미지·프롬프트·API 키·제공자 오류 원문은 기록하지 않는다.
- 실제 생성은 선택한 제공자에 사진·요청을 보내며 API 요금이 발생한다. 비용 확인은 제공자 대시보드에서 한다.

## 생성과 수정

- 기본 요청은 1장. 2~4장은 한 장씩 순서대로 호출하며 완료한 결과부터 화면에 추가한다.
- 중복 클릭을 막고 실패하면 나머지 호출을 중단한다. 타임아웃·네트워크 오류를 자동 재시도하지 않는다. 이미 끝난 시안은 남는다.
- 제공자 대기 시간은 120초, 클라이언트는 135초다. 타임아웃 시 제공자가 이미 처리했을 가능성을 안내한다.
- 참고자료는 14장, 요청 전체는 24MiB까지다. 파일 원본 합계는 대략 17MB 이하로 안내한다. 초과 시 일부 자료를 조용히 빼거나 재압축하지 않는다.
- 제품 보존 기본 프롬프트를 포함하고 사진 순서·역할을 명시한다. 수정 요청은 선택한 결과를 첫 사진으로 보내며 해당 결과에 사용했던 제품 원본과 치수를 유지한다.
- `[styled-image]` 로그로 생성 단계와 느린 동기 계산을 확인한다. 브라우저 로그에는 경로와 입력 동작을 포함한다.
- 생성 중에는 스피너·움직이는 막대·경과 시간·현재 장수를 표시한다. 요청 영역 전체를 disabled fieldset으로 잠그며 빠른 요청, 비율, 장수, 재전송을 막는다. 자료와 결과 선택도 잠근다. 성공·실패 모두 finally에서 잠금을 해제한다.
- 제공자 오류의 상세 메시지는 키와 긴 인코딩 문자열을 가린 뒤 최대 600자로 요청자에게 반환한다. 서버 로그에는 제공자 상세 오류를 기록하지 않는다.

## 검증

- `npm run verify:styled-image`: 요청 검증, 원본 바이트 전송, 모델별 요청/응답, 비율, 수정 시 원본 보존.
- `npm run verify:styled-image-deployment`: 기존 개발 계정으로 모델 조회 및 비로그인 차단 확인. 유료 생성은 하지 않는다.
- `npm run verify:styled-cuts`, `npm run verify:diagnostics`, `npm run lint`, `npm run build`.
- 2026-09-15 운영 함수 v1에서 네 모델 조회와 비로그인 차단을 확인했다. 실제 제품 이미지 생성 품질은 사용자가 등록한 자료로 확인한다.
- 같은 날 v3에서 Google JPEG 출력 수정 후 사용자 참고자료 3장으로 재요청했다. 약 31초 후 실패 로그 없이 작업 종료를 확인했다. 생성 중 진행 패널과 요청 필드·빠른 요청 버튼 비활성화는 실제 브라우저에서 확인했다. 이후 화면이 새로고침되어 완성 이미지 자체의 시각 검수는 하지 못했다.
- TypeScript, 기능 검증, 기존 연출컷/진단 검증, 스튜디오 단독 프로덕션 번들은 통과했다. 전체 앱 `npm run build`는 모듈 변환 후 Windows 프로세스 종료 코드 `-1073740791`로 중단됐다. WASM 및 CSS 최적화 비활성 검증에서도 전체 빌드는 중단돼 원인은 아직 확정하지 않았다. 개발 서버의 연출컷 화면은 실행·모델 선택을 확인했다.

## 디렉터와 화질 선택 (2026-09-15)

- `direct` 액션은 기존 OpenAI 키로 선택한 디렉터 모델의 Chat Completions를 호출한다. 디렉터 목록은 `models` 조회 때 OpenAI `/v1/models`에서 받아, 비전 가능한 GPT-4.1·GPT-4o·GPT-5+ 별칭만 보여 준다. 날짜 스냅샷·이미지·오디오·실시간 모델은 뺀다. 기본은 조회된 목록의 `gpt-5.6-luna`(없으면 mini/nano, 그다음 최신 계열). 모든 원본 사진과 역할을 보내며 strict JSON schema로 요약·상세 지시문·필수 확인 질문을 받는다. `store: false`. GPT-5+는 `max_completion_tokens`를 쓴다. [모델 문서](https://developers.openai.com/api/docs/models), [구조화 출력](https://developers.openai.com/api/docs/guides/structured-outputs).
- 디렉터는 제품 정체성과 연출 참고자료를 구별하고, 보이지 않는 구조·로고·소재 성분·치수를 추측하지 않도록 지시한다. 모델 판단이므로 결과 원본 비교는 계속 필요하다.
- 스튜디오의 모델·출력 설정은 접을 수 있다. 접힌 줄에 현재 이미지 모델과 디렉터 모델을 보여 준다.
- 기본은 분석 후 바로 이미지 생성. `생성 전에 디렉터 지시문 확인·수정`을 켜면 요약과 편집 가능한 상세 지시문을 먼저 표시한다. 제품 보존 기본 지시와 원래 요청은 편집 영역 밖에서 항상 유지한다.
- 동일 자료의 확인→생성에서는 디렉터를 다시 호출하지 않는다. 요청·제품정보·역할·사진 ID·모델·설정·편집 대상이 달라지면 계획이 무효화된다. 질문이 있거나 디렉터 응답이 불완전하면 이미지 API를 호출하지 않는다.
- 분석은 배치당 한 번, 이미지 생성은 장당 한 번이다. 분석의 OpenAI 과금 및 사진 전송을 UI에서 안내한다. 디렉터 제한 시간 60초, 이미지 제한 시간 120초. 실패 시 자동 재시도하지 않는다.
- OpenAI 표준 픽셀: 1024×1024 / 1024×1280 / 960×1280 / 1536×864. 고해상도는 각 변의 2배이며 모델의 최대 변·총 픽셀·16px 배수 조건을 검증한다. 고해상도는 더 오래 걸리며 일부 큰 크기는 제공자 실험적 지원 범위다.
- 생성 시 사용한 요약·상세 지시문·설정을 대화 이력과 버전에 남긴다(기존처럼 현재 메모리만). 고해상도 출력은 최대 64MiB 인코딩 데이터까지 읽되 입력 제한은 기존 24MiB로 유지한다.

## 이어가기 자료 선택과 확대 보기

- 이어가기 요청에 선택한 결과와 원본 제품 사진을 기본 포함하고, 현재 등록된 사진을 추가 선택하거나 여러 장 업로드할 수 있다. 추가 사진 역할은 연출 레퍼런스/제품 사진/원단 디테일/끈·구조/크기 비교로 지정한다.
- 컷별 추가 선택을 `editInputs`에 보관한다(기존 API 시험 모드는 메모리만). 다른 컷의 선택과 섞이지 않는다. 추가 선택/역할 변경은 디렉터 계획을 무효화한다.
- 디렉터와 이미지 생성은 같은 이미지 목록을 사용한다. 편집 대상이 첫 사진, 원본이 다음, 추가 선택 사진이 마지막이다. 중복은 제거하고 원본 역할이 추가 역할보다 우선한다. 기존 14장/용량 한도를 적용한다.
- 결과 클릭은 네이티브 dialog로 크게 보기를 연다. 화면 맞춤/원본 크기 전환, Escape·닫기 버튼, 별도 다운로드를 제공한다.
- 요청 계약 검증과 TypeScript 통과. UI 검증용 응답으로 사진 선택·추가·역할 변경과 확대 보기/원본 크기/Escape 닫기, 생성 중 추가 자료 잠금을 확인했다. 이번 변경은 유료 생성 없이 검증했다. 프로덕션 번들은 기존 Windows 빌드 중단 문제로 모듈 변환 뒤 종료됐다.

## 이어가기 선택 방식 수정

- 기존 자동 포함 규칙을 폐기한다. 이어가기는 `editInputs[versionId]`에 체크된 이미지 ID만 순서대로 전송한다. 시안/원본/새 업로드 모두 체크박스로 선택하며 새 업로드도 자동 선택하지 않는다. 선택이 없으면 버튼과 요청 구성 단계에서 차단한다.
- 새 선택 기본 역할은 `요청 참고`다. 추가 사진을 일괄적으로 배경·구도·조명에 제한하지 않고 이번 명령에 맞게 해석하도록 지시한다. 사용자가 `연출 레퍼런스`를 지정한 경우만 해당 범위를 적용한다.
- 첫 사진을 무조건 편집 대상으로 취급하던 지시를 제거한다. 체크된 사진의 역할에서 편집 대상을 찾아 실제 사진 번호로 표시하고, 없으면 이전 시안이 전달되지 않았음을 명시한다.
- 카드형 체크박스, 선택 테두리, 사진 번호, 역할 선택, 작은 업로드 버튼으로 UI를 교체했다. 요청 대화에도 실제 전달한 사진·번호·역할을 표시한다. 디렉터 분석 로그에 첨부 수와 역할만 기록한다.
- TypeScript, 선택 자료 계약 테스트, 연출컷/진단 검증 통과. UI 검증용 API로 원본과 시안은 미선택하고 추가한 JPEG 한 장만 체크한 뒤 요청했을 때 디렉터 수신 목록과 생성 대화가 해당 한 장만 포함하는 것을 확인했다. 실제 제공자의 이미지 해석 정확도는 이 테스트가 보장하지 않는다.
