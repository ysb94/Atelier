# 외근 관리와 실제 입력 야근 집계

2026-11-03 공유 운영 DB 적용·검증 완료. main 화면 배포는 미실시.

## 화면과 집계

- 운영지원 → 근태 → 야근 관리 옆에 외근 관리를 추가한다. 해당 월과 겹치는 외근의 직원·부서·기간·매일 시간·장소·사유·상태를 표시한다. 기존 즉시 등록·취소·자동 출퇴근·복귀 규칙은 변경하지 않는다.
- My home → 야근에서 기존 부서 승인 절차를 거친 신청에 실제 시작·종료와 휴게시간을 별도 입력한다. 승인 시간은 실제 입력칸에 자동 복사하지 않는다.
- 운영지원 야근 목록과 홈의 이번 달 야근은 승인된 신청 + 최신 실제 입력이 모두 있는 건만 사용한다. 출퇴근 원본·정정·외근 자동 퇴근으로 야근을 추정하지 않는다.
- 실제 입력에서 휴게 분을 뺀 시간만 누적한다. 약정 연장근로시간은 기존 명부의 `inclusive_overtime_hours`를 그대로 읽는다. 약정 초과 표시는 `max(실제 누적 분 - 약정 시간×60, 0)`이다. 임금 금액 계산은 추가하지 않는다.
- 실제 입력은 승인 범위 안의 완료된 근무만 허용한다. 승인 범위를 넘는 근무는 추가 신청이 필요하다. 다음 날 종료를 지원하며 시작일의 월에 합산한다.
- 과거 완료 신청의 실제 시간을 퇴근 기록으로 소급 생성하지 않는다. 기존 신청·출퇴근 원본을 삭제하거나 다시 저장하지 않는다. 과거 건도 실제 시간을 직접 입력한 뒤 반영된다.
- 외근 야근의 휴가 보상 선택·지급·임금 누적 제외는 별도 지급 기준과 승인 절차를 정한 뒤 작업한다. 이번 외근 목록은 휴가를 지급하거나 야근을 자동 생성하지 않는다.

## 데이터·권한·동기화

- 추가 마이그레이션: `20261103081759_overtime_actual_reports.sql`.
- 새 표 `overtime_actual_reports`는 신청 ID + 수정 버전의 추가 전용 이력이다. 원본 승인 신청/출퇴근/연차/기존 RLS·함수는 변경하지 않는다.
- 새 표 조회는 기존 신청 원본의 조회 권한과 활성 직원 조건을 따른다. 입력은 같은 회사의 본인 승인 야근만 가능하다. 운영지원의 타인 실제 기록 수정 권한은 만들지 않는다. 익명 접근·이력 UPDATE/DELETE는 차단한다.
- 모든 함수와 최신 버전 뷰는 invoker다. INSERT 트리거가 원본·입력 범위·현재 시각·분 단위·휴게·버전을 검증한다. 신청 전이와 같은 직원 advisory lock으로 동시 입력을 직렬화하고, 버전 충돌은 거부한다.
- 최신 수정 1개만 합산한다. 취소·반려·권한 해제 등 원본 상태를 조회 때 다시 확인한다. 이전 실제 입력 이력은 남긴다.
- 실제 입력 저장 후 공유 Query 캐시를 무효화하며 활성 화면은 최대 30초 간격으로 갱신한다. 사용자별 캐시 키를 사용한다.
- 알림은 기존 야근 신청/승인/반려 공통 연결을 그대로 사용한다. 실제 입력은 새 승인 신청이나 새 알림을 만들지 않으며 기존 읽음 기록도 바꾸지 않는다.
- 새 DB 연결 전에는 입력을 차단하고 ‘연결 대기’를 표시한다. 이전의 퇴근 기반 추정 집계로 되돌아가지 않는다.

## 검증

- `npm run verify:overtime-actuals`: 계산·홈 동일 기준, 격리 PGlite 권한/원본 보존/수정 이력/버전 충돌, 외부 요청을 막은 브라우저의 개인 입력→관리 집계→외근 목록.
- 일반 직원의 본인 입력, 타 직원/다른 회사/비활성/익명 차단, 운영지원 읽기 전용, 미승인·취소·미입력 제외, 승인 범위·휴게·자정 경계, 저장 실패 시 입력 보존을 확인한다.
- 사용자 승인 후 공유 DB에 적용했다. 데이터 비교값은 DB 내부 임시 표에서만 비교하고 폐기해 로컬로 반출하지 않았다. 기존 원본·RLS·실행 권한 보존 검사를 통과했으며, 실제 인증 역할의 등록·승인·실제 입력·전체 활성 계정의 조회/쓰기 경계 검증은 모두 롤백했다.
