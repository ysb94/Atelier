# 다음 달 출근시간 지정 알림

## 동작

다음 달 1일의 7일 전부터 매일 오전 9시(Asia/Seoul)에 담당 부서의 미지정 출근시간을 알린다. 12월은 11월 24일, 1월은 12월 25일, 3월은 평년 2월 22일/윤년 2월 23일에 시작한다. 대상 월이 시작돼도 미완료면 계속 안내한다. 이전 달을 소급 생성하지 않는다.

수신자는 같은 회사의 활성 계정 중 현재 해당 부서의 지정 승인자·대체 승인자다. 승인 종류가 중복되거나 같은 사람이 두 역할이어도 부서·월별 업무 한 건이다. 직책·예외 운영자라는 이유만으로 추가 발송하지 않는다. 담당자가 없는 부서는 수신자를 자동 지정하지 않는다.

같은 부서의 활성 본사 관리 대상 직원에서 출퇴근 제외자를 빼고, 대상 월의 개인 설정 우선·부서 설정 보완 규칙으로 판정한다. 이전 달 시간은 사용하지 않는다. 전체 완료·부서 비활성·담당자 해제 시 처리 필요 표시가 사라진다. 현재/미래 대상 월에서 인원이나 설정이 바뀌면 재판정한다. 과거에 종료된 월은 새 입사 때문에 다시 열지 않는다.

## 서버와 성능

로컬 SQL: `20261105101454_attendance_start_reminders.sql`. 사용자 승인 후 공유 DB에 **`20261105104214_attendance_start_reminders`**로 적용했다. test/main 사이트 배포는 하지 않았다.

- app 비공개 표 1개: 회사·부서·월별 기록, 일별 발행 버전과 수신자별 읽음. RLS를 켜고 클라이언트의 직접 표 접근을 금지한다.
- 보조 함수: 기존 workforce 함수가 있으면 재사용하고, 미적용 서버에서는 현재 부서 UUID 분류를 사용한다. 새 관리자 권한을 만들지 않는다.
- 발행 함수: 서버 시각만 사용하고 트랜잭션 advisory lock과 일별 버전으로 중복을 막는다. 완료된 행에는 반복 저장하지 않는다. 다른 cron은 변경하지 않고 새 작업 하나만 UTC `0 0 * * *`에 추가한다.
- 조회/읽음 RPC와 app 보호 함수: 활성 계정·회사·현재 담당 지정·현재 버전을 서버에서 검사한다. 조회는 쓰기를 수행하지 않는다. 실행 권한은 필요한 조회/읽음 경로만 authenticated에 허용한다.
- 버전은 발행 일별 번호와 미지정 직원 UUID 집합의 지문을 결합한다. 이전 화면의 읽음 요청은 다음 날 또는 변경된 직원 집합을 읽음으로 만들지 못한다. UUID 집합 자체는 응답하지 않는다.
- 본인 담당 부서의 현재/미래 및 과거 미완료 행만 진행 집계한다. 과거 완료된 행은 표에 보존하지만 반복 조회/재계산하지 않는다. 일반 직원은 알림 조회를 실행하지 않는다.

적용 시 최초 실행은 그날의 다음 달이 안내 시작 기간에 해당할 때만 생성한다. 기존 설정·출퇴근·승인·직원·권한 정책이나 다른 알림 자료는 바꾸지 않는다.

## 화면 연결

종합 알림과 My home ‘담당 부서 출근시간’은 같은 쿼리·서버 읽음을 사용한다. 전용 알림 종류/대상 source와 `attendance` 탭을 공통 모델에 추가한다. 기기 푸시 후보에서는 이 종류만 제외한다.

연결은 `/settings/profile?part=attendance&month=YYYY-MM`. 월별 미지정 인원과 필터를 표시하며 검색은 전체 완료 건수에 영향을 주지 않는다. 해당 월과 직원/설정이 정상 표시된 뒤 읽음을 저장한다. 조회·읽음 실패는 완료로 처리하지 않고 재시도 UI를 제공한다. 읽었어도 실제 미지정 직원이 있으면 처리할 일은 유지한다. 저장 성공 시 설정과 알림 캐시를 함께 무효화하고, 다른 기기의 변화는 공통 coordinator의 30초 조회로 반영한다. 서버 미적용 상태는 자동 반복 조회를 중단한다.

## 검증

Node 22에서 아래 검증을 실행한다. DB·브라우저 fixture는 운영 데이터나 외부 API를 사용하지 않는다.

```text
node scripts/verify-attendance-start-reminders.mjs
node scripts/verify-attendance-start-reminders-db.mjs
node scripts/verify-attendance-start-reminders-browser.mjs
npm run verify:my-home-notifications
npm run verify:desktop-notifications
npm run verify:workflow-diagnostics
npm run build
npm run structure:map
npm run verify:structure-map
```

격리 PostgreSQL은 월/윤년/연도 및 09:00 경계, 중복 발행·읽음, 개인/공통 설정 완료, 월 시작 후 지속, 권한·소속·부서 변경, 오래된 버전 차단과 기존 설정 보존을 확인했다. 브라우저는 실제 설정 패널·종합 알림·API 어댑터로 대상 월, 미지정 필터, 저장/완료, 읽음 공유/실패 재시도, 계정 전환과 모바일을 검증했다. Node 22 빌드·기존 알림·기기 알림·숨겨진 일정·업무 단계 진단 및 구조도 검증도 통과했다.

공유 DB에서는 활성 계정 39개의 현재 담당 범위를 원본 지정 내역과 대조하고, 비공개 표·발행 함수·anon 접근 차단 79건과 수신자별 읽음 11건을 확인했다. 임시 알림만 트랜잭션 안에서 넣어 검증 후 전부 롤백했다. 기존 직원·부서·명부·출근시간·제외자·승인자·권한 지정·출퇴근·근태 신청 9개 표 원본, 기존 정책·표 권한·함수 및 cron 설정 지문은 모두 동일하다. 보안 진단의 추가 항목은 의도적으로 직접 접근을 막은 app 비공개 표의 `rls_enabled_no_policy` INFO 한 건뿐이다.

`cron.timezone=GMT`, DB 시간대 UTC와 새 작업의 `0 0 * * *` 활성화를 확인했다. 적용일인 2026-11-05에는 발행 기간이 아니므로 저장된 알림은 0건이며, 첫 대상은 2026년 12월(11월 24일부터)이다. 원본 지문과 검증 결과는 Git 제외 대상 `docs/backups/attendance-start-reminders-*-20261105.json`에 보관한다. test/main 배포는 별도 대상이다.
