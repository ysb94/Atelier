# 외근일 출근 기준 변경

## 동작

- 외근 신청의 `당일 출근 기준 변경`을 선택하면 외근 시작일의 출근 기준을 별도로 지정한다. 회사의 출근시간 선택지를 사용하며 월별 직원/부서 설정은 수정하지 않는다.
- 평소 09~18시인 직원이 당일 기준을 10시로 지정하고 16~20시 외근을 등록하면 정규 근무는 10~19시, 외근 추가 근무는 19~20시 1시간이다. 실제 출근 기록 10시와 외근 시작 16시는 서로 바꾸지 않는다.
- 오늘/미래 날짜의 단일 근무일에만 적용한다. 밤샘 외근도 시작 근무일만 변경한다. 다음 날은 월별 기준을 사용한다. 기존 여러 날 반복 외근에는 지정하지 않는다.
- 등록된 해당 날짜의 외근 전체가 같은 기준을 사용한다. 서로 다른 기준은 직원별 잠금 아래 거부한다. 같은 기준의 외근 여러 건은 허용하며, 마지막 유효 외근까지 취소하면 월별 기준으로 복귀한다.
- 취소는 이 외근에 연결된 당일 기준도 해제한다. 출퇴근 원본·이미 작성된 지각 사유서·취소된 외근의 지정 값은 삭제하거나 수정하지 않는다. 지난 날짜의 기준 변경은 새 외근으로 소급 등록할 수 없다.

## 연결

- 서버: 본인 근무일 기준 RPC, 근무 확인의 예정 퇴근, 지각 사유서의 실제 판정, 누적 지각 조회에 공통 날짜별 기준을 적용한다. 근무 확인의 외근 중 중단·사무실 복귀·자동 출퇴근 시각은 기존 외근 일정/기록 로직을 유지한다.
- 화면: 퇴근 안내, 홈 지각 횟수, 운영지원 지각/근태 달력·요약·내보내기, 외근 추가 근무 표시, My Schedule 외근 상세가 당일 지정 값을 사용한다. 기존 야근 신청에 연결된 실제 입력 누적은 수정하거나 추정 생성하지 않는다.
- 등록·취소 후 근무일 기준/근태/외근/지각/홈 조회를 함께 갱신한다. 새 승인·업무 알림이나 별도 읽음 상태는 만들지 않고 기존 외근 흐름을 사용한다.

## DB와 적용 상태

- `20261103090128_offsite_workday_start_override.sql`을 준비했으며 **공유 Supabase 미적용**이다. 기존 신청에 nullable `offsite_work_start` 열과 부분 인덱스·검증 트리거를 추가한다. 기존 행은 null이며 기존 배포 코드/권한/RLS/월별 기준과 호환된다.
- 원본 변경을 막고 본인·재직·동일 회사·선택지·지정 날짜·중복 기준을 검증한다. 직원 잠금은 기존 근태/신청과 같은 키다. 지각 사유서 저장도 이 잠금 아래 기준을 읽는다.
- 내부 공통 함수는 private `app` 스키마이며 직원 직접 실행을 막는다. 새 일별 누적 조회 공개 함수는 invoker이고 익명 실행을 금지한다. 기존 월별 조회 RPC는 유지하고, 새 조회에서도 본인/담당자 권한을 확인한다.
- 서버가 `offsiteWorkdayStartSupported`를 반환하기 전에는 새 항목을 비활성화하고 `서버 적용 대기 중`을 표시한다. 저장 직전에도 확인한다. 기존 외근 등록은 계속 사용할 수 있다.
- 적용 전 함수 원문과 스키마/정책/실행 권한 메타데이터는 로컬 `docs/backups/offsite-workday-start-*-before-20261103.*` 및 `offsite-workday-start-before-20261103.json`에 보관했다. 인사 원문을 반출하지 않았다. 실제 적용은 프로젝트의 공유 DB 별도 승인 단계에서 수행한다. 적용 직전에 함수/스키마 스냅샷 일치를 다시 확인한다.

## 검증

- `npm run verify:offsite-workday-start`: 10시 사무실 출근·16~20시 외근, 19시 퇴근 기준·추가 1시간, 실제 지각 10:06, 다음 날/다른 직원/취소, 날짜별 달력/요약, 밤샘 시작일 귀속을 검증한다.
- 격리 PGlite에서 실제 기존 신청 검증 함수와 마이그레이션을 실행한다. 기존 시각/정책/함수 ACL 보존, 동일 날짜 충돌·원본 수정·과거 지정 차단, 취소 후 복구, 서버 근무 확인/지각 사유서, 본인/타인/비활성/익명 권한을 확인한다.
- 외부 접속을 차단한 브라우저에서 실제 신청 화면의 선택·19시 미리보기·16~20시 저장·달력 상세·서버 미적용 차단과 실제 운영지원 외근 목록의 추가 1시간 표시를 확인한다. 기존 밤샘 출퇴근과 실제 입력 야근 집계도 회귀 검증한다.
