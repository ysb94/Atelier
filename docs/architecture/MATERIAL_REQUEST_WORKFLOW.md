# 자재요청 저장과 권한

기획과 중국 업무의 자재요청은 같은 서버 요청 ID를 사용한다. 화면 미리보기의 메모리 값은 가져오지 않는다. 샘플 작업지시서·기획안 테이블, 기존 역할과 알림은 변경하지 않는다.

- 요청 표에는 작성 상태, 현재 제목·브랜드, 저장 버전과 요청자를 기록한다. 전송하면 별도 회차에 본문과 첨부 참조가 고정된다. 전송 전 요청만 삭제할 수 있고 전송 이력은 보존한다.
- 같은 회사에서 기획 업무 권한을 가진 직원은 본인 요청과 공유된 목록을 본다. 동료 작성 중 초안과 첨부는 보이지 않는다. 운영 담당자는 전송된 회차를 확인하고 등록된 재직 중국팀 직원에게 배정한다. 작업자는 본인 회차만 보며 확인 후 발송할 수 있다. 미발송 건을 다른 작업자에게 재배정하면 이전 확인 상태를 초기화한다.
- 요청자만 발송 후 수령과 만족도를 기록한다. 10점이면 완료, 1~9점이면 이전 회차를 보존하고 다음 요청을 작성할 수 있다.
- 목록은 요약만 읽고 상세를 열 때 본문과 비공개 첨부를 받는다. 첨부는 파일당 10MB이며 요청·회차의 조회 권한을 따른다. 저장되지 않은 파일은 열리지 않으며 같은 화면에서 저장을 재시도하면 이미 올라간 파일을 재사용한다.
- 저장 시 서버가 역할, 회사, 회차, 현재 단계와 버전을 검사한다. 계정 전환과 새로고침에서는 새 계정으로 서버에서 다시 읽으며, 다른 화면에서 변경한 내용은 새로 조회할 수 있다.

스키마: `20261106133000_material_request_workflow.sql`. 내부 표 2개, 비공개 버킷 1개와 해당 저장소 정책 2개, 공개 조회·변경 RPC 2개와 내부 함수 5개를 추가한다. 기존 데이터 수정이나 데이터 이관은 없다.

검증: `node scripts/verify-material-request-workflow.mjs`, `node scripts/verify-material-request-browser.mjs`. 브라우저 검증은 외부 접속 없이 로컬 PostgreSQL 테스트 엔진에서 역할을 바꿔 실행한다. 공유 DB 반영과 사이트 배포는 별도다.
